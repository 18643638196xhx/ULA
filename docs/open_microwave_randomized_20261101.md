# 微波炉 ULA：随机化场景 50 轮评测

## 目的与设置

评测任务为 `open_microwave`，使用现有不依赖微波炉 CAD 的 ULA：传统视觉/几何接近把手，VLA 只负责局部闭爪，传统控制试拉并逐段开门。独立入口加载原微波炉控制器，不修改原控制器、感知器、杯子或药瓶控制逻辑。

对照历史干净场景 `microwave_repair_50eps_seed0_20261025_v2`：完整成功 39/50（78%），官方评分成功 44/50（88%），剔除第一轮后完整成功样本平均 8.219 s。完整成功要求原 ULA 全流程通过并满足官方评分；仅官方评分成功但中途被视觉规则停止，不算完整成功。

本次唯一有意改变的场景设置来自 RoboTwin `demo_randomized.yml`：随机背景、桌面杂物、随机光照和最多 3 cm 桌面高度扰动；头部相机距离扰动为 0。保留 RGB-D、腕部相机、原规划器及安全检查。原始 seed 0–49 连续尝试，不跳过初始化失败、不补种子。微波炉型号仍由原任务随机生成，没有固定成已知 CAD 型号。

固定指令为 `Open the microwave.`，不是官方 unseen 指令采样；因此这是随机场景对照，不是完整官方 randomized benchmark。随机化会改变随机数消耗，同一 seed 在 clean/randomized 中不保证相同型号和位姿。

沿用参数：接近距离 2.5 cm、初始夹爪命令 0.45、VLA 最多 100 步、视觉开门目标 70°、每段最多 3°、最多 40 段。控制期间不读取微波炉根位姿、门关节或接触真值；仿真场景生成/稳定性检查属于环境，官方评分和门关节诊断仅在控制结束后读取。

## 运行与隔离

新增入口为 `scripts/run_open_microwave_randomized.py` 和 `.sh`。仅在当前独立进程内覆盖配置函数与报告写出，退出后恢复；报告持续保存实际随机化配置、完整成功率、官方评分成功率、初始化失败、来源哈希和进程状态。原微波炉 runner、原 launcher 及受保护放置文件不变。

GPU 7 同卡共享模型、规划、仿真和视觉；JAX 分配器预算 40%、主 PyTorch 8%、视觉 PyTorch 10%，关闭预分配。这不是硬显存或算力隔离，与历史视觉放在 GPU 0 的耗时不能作严格配对速度比较。模型/视觉常驻复用。

```bash
cd /data1/xuhuixin/ula
GPU=7 MICROWAVE_JAX_FRACTION=0.40 \
MICROWAVE_MAIN_TORCH_FRACTION=0.08 MICROWAVE_VISION_MEMORY_FRACTION=0.10 \
MAX_JOBS=2 OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
bash scripts/run_open_microwave_randomized.sh \
  --mode hybrid --episodes 50 --seed 0 \
  --approach-clearance 0.025 --approach-gripper 0.45 \
  --max-vla-steps 100 --target-angle-deg 70 \
  --output /data1/xuhuixin/ula/results/microwave_randomized_50eps_seed0_20261101_v1
```

输出目录、日志均使用新前缀 `microwave_randomized_50eps_seed0_20261101_v1`，不覆盖历史结果。每轮正常初始化后保存初始、接近、闭爪和最终画面（具体阶段是否存在取决于失败位置），感知原始 RGB-D 另存。初始化失败可能无截图，不用其他轮次替代。

新增 3 项 CPU 配置/统计/隔离测试，全量 **280 项通过**。

## 最终结果（50/50 已结束）

`report.json` 的 `run_status=finished`、`completed_episodes=50`。未替换失败种子，运行期间未改阈值或源文件。视觉进程启动一次并已关闭，主进程已退出；退出码 1 表示该入口记录了失败轮，不是只运行了一部分。

| 指标 | 历史 clean 场景 | 本次 randomized 场景 |
| --- | --- | --- |
| 完整任务成功率／全部尝试 | 78%（39/50） | **16%（8/50）** |
| RoboTwin 官方评分成功率／全部尝试 | 88%（44/50） | **16%（8/50）** |
| 初始化失败 | 0 | 9 |
| 正常初始化后的完整成功率 | 78%（39/50） | **19.5%（8/41）** |
| 排除第一轮后的成功完成均时 | 8.219 s（38 个样本） | **16.996 s（8 个样本）** |

首轮 seed 0 本次失败，剔除它不影响成功耗时样本；成功率仍使用全部 50 次尝试。排除首轮后的全部尝试均时为 10.519 s（49 个样本），不称为完成时间。成功 seeds：8、11、12、21、33、35、36、44。

### 失败分布

| 阶段 | 次数 | seed | 可确认的停止原因 |
| --- | --- | --- | --- |
| 场景初始化 | 9 | 10、14、27、31、37、38、39、45、49 | 杂物未通过环境稳定性检查，控制未开始 |
| 初始视觉定位 | 16 | 1、3、4、7、9、18、19、20、23、24、29、30、40、41、43、46 | 头部和腕部相机均未返回通过检查的门/把手组合，尚未执行传统接近 |
| 闭爪后的视觉基准 | 14 | 0、2、6、13、15、16、17、22、26、28、32、34、47、48 | 已完成接近和 VLA 闭爪候选，但无法建立通过检查的当前门/把手观测，未开始传统试拉 |
| 传统试拉／开门 | 3 | 5、25、42 | 没有得到可信的门面旋转／把手随动证据，停止继续拉门 |

初始化失败记录涉及醋瓶（10、14）、酒杯（27）、风扇（31）、木块与瓶子（37）、瓶子（38、39）、酒杯与木块（45）、橄榄油瓶（49）。不将其归为机器人抓取失败。

初始视觉拒绝包括未检测到门、把手框退化为整机大小、门的左右边缘被截断或门面几何不可信，不能统一称为“没看见物体”。闭爪后的拒绝还包括夹爪遮挡后可见把手片段太短、腕部视角门面不足等。日志能确认规则停止，不能证明这 14 次物理上都没抓住；没有按截图把候选闭爪直接计为成功抓取。

seed 5 第一段试拉后即停止；25 在最后一次通过观测时视觉角约 3.37°；42 约 18.00°。三轮都未通过官方评分。终态及离散观测不能单独区分空夹、滑动和视觉误拒绝，需另行针对连续过程诊断。

没有 VLA 动作预算耗尽的失败。共 30/50 次尝试停在初始视觉或闭爪后视觉基准，**因此本批主要暴露出感知与可观测性不足，不宜概括为传统控制拉不开门或 VLA 完全不会抓。** 本次没有已通过官方评分却被完整流程额外判失败的轮次。

### 成功样本的时间分解

以下为同一组 8 个成功样本的平均主机墙钟时间，阶段互不重叠：

| 阶段 | 平均耗时 |
| --- | --- |
| 环境设置 | 0.381 s |
| 传统接近（含初始感知） | 7.458 s |
| VLA 局部闭爪 | 0.424 s |
| 闭爪后视觉基准 | 0.070 s |
| 传统试拉与开门 | 7.589 s |
| 保存图片等 | 1.074 s |
| 总计（含微小计时差） | 16.996 s |

接近阶段中规划查询累计平均 6.509 s、平均 5.375 次查询；包含失败候选和后续段，不等于每次查询都是重试。传统开门平均 26.125 段。运行日志有多次规划候选失败，但这 16 次初始阶段的最终错误全部为视觉拒绝，不能把它们改计成规划失败。

运行中观察到所有 GPU 的其他共享负载明显上升；本次同卡视觉与历史分卡视觉也不同。成功样本集合不同，因此不能将 8.219→16.996 s 全部归因于随机场景、某一算法或显存分配。
