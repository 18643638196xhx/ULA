# 药瓶改用 place_empty_cup 方法

本次迁移对应杯子当前的“已知 CAD、无额外试抬”版本，即随机场景 41/50 那批的执行方法，不是另一版无模型 ICP 方法。迁移不意味着药瓶会获得相同成功率。

## 现在怎样执行

开始时用颜色、深度和语义识别橙白药瓶与蓝色方垫，再以药瓶自身 CAD 做视觉定位。传统控制使用原生抓取姿态选择器生成接近动作，只执行预抓取移动，最终夹取留给 VLA。

VLA 执行期间，连续 3 个动作的夹爪控制状态低于 0.05 就交接，不再另外判断 TCP 是否距离药瓶表面 1.5 cm，也不在交接前等待夹爪关节稳定。不额外试抬。连续闭爪只是交接许可，不是“确实夹稳”的证据。与杯子一样，最多允许一次由视觉桌面支撑证据授权的停滞恢复；重试共享本轮总动作预算，不读取物体真值来决定重抓。

放置阶段重新用当前 RGB-D 做全局 FoundationPose 配准，直接调用杯子的 `KnownCupVision.estimate` CAD 检查，不再使用药瓶专用的机器人搬运位姿先验或上一姿态跟踪。垫子中心沿用本轮初始时验证过的视觉位置，前提是静态垫子没有移动。

定位通过后，直接调用杯子的 `adapters.placement.finish_placement`：计算药瓶相对机器人手的关系，以药瓶功能点对准垫子中心，使用抓前视觉朝向作为直立参考；搜索 7 个偏航和 3 个搬运高度，搬运及下降两段都规划成功才执行，然后松爪、撤离。这里不再调用药瓶原来的倾斜释放搜索、抓后头腕多轮定位策略、运输过程复查和额外关节等待。杯子原有的执行检查仍保留，没有修改公共函数。

## 必须保留的任务区别

杯子和药瓶不能使用相同 CAD 或相同接触点编号。因此外观、CAD、抓取接触标注和放置功能点换成药瓶自己的。药瓶原任务会出现在桌面两侧，默认根据视觉估计的位置选左/右臂，而不是强制左臂；可用 `--arm` 显式指定。默认 VLA 总预算与杯子一致为 500 个动作，旧药瓶是 300。

场景仍是官方 `move_pillbottle_pad`，最终仍调用原药瓶任务的成功判定，不把评分标准换成杯子的标准。当前固定预配置 base1；不是在场景中读取模型 ID 再选择模型，也不是五种药瓶的混合评测。

控制期间屏蔽任务真值成功检查，禁用策略真值诊断。为了复用杯子评测记录，任务内部设置 `cup=药瓶`、`coaster=垫子` 的兼容别名；视觉控制分支不读取这些对象的真实位置，相关对象读数只用于控制结束后的原有评分/诊断。

## 代码与启动

新入口是 `scripts/run_move_pillbottle_pad_cup_method.sh`。调度、闭爪监视、恢复、试抬绕过直接复用 `scripts/run_cup_no_trial_randomized.py` 及其杯子执行器；任务几何适配位于 `adapters/pillbottle_focus/cup_method.py`，视觉工作进程位于 `scripts/perceive_pillbottle_cup_method.py`。

没有修改杯子、微波炉、旧药瓶入口或 RoboTwin 原任务文件。此前“只改颜色＋深度＋语义”的药瓶分支仍保留作对照，新的方法必须使用本页的新入口。

```bash
cd /data1/xuhuixin/ula
GPU=7 PILLBOTTLE_RANDOM_VISION_GPU=6 \
XLA_PYTHON_CLIENT_ALLOCATOR=platform MAX_JOBS=2 \
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
bash scripts/run_move_pillbottle_pad_cup_method.sh \
  --episodes 50 --seed 0 \
  --output /data1/xuhuixin/ula/results/pillbottle_cup_method_randomized_50valid_seed0_v1 \
  > /data1/xuhuixin/ula/results/pillbottle_cup_method_randomized_50valid_seed0_v1.launcher.log 2>&1
```

初始化失败单独记录并补足 50 个有效场景；其余失败不筛除。输出目录必须为空。该命令为前台启动，可在自己的终端会话中运行；本次代码迁移不自动开启新的完整 50 次实验。

## 验证记录

358 项 CPU 回归测试通过。新增 9 项检查了实际复用杯子 CAD 函数和放置函数、无距离闭爪接管、不读在线物体真值、跨轮清除垫子缓存、生成物体前配置模型、异常恢复，以及 RoboTwin 相对资源目录处理。

三次完整流程验证已结束，记录在 `results/pillbottle_cup_method_smoke3_20261102_v1/`。seed 0、1、2 均通过接近并触发了杯子式闭爪交接，分别在 VLA 第 33、127、35 个动作交接，未执行试抬。完整结果为 0/3：seed 0、2 执行完原杯子搬运、下降、松爪和撤离，但最终药瓶评分失败；seed 1 在放置前重新识别药瓶时被拒绝，未继续放置。不能把“流程已迁移”或“放置动作执行完”写成任务成功，也不能仅凭最终结果断言具体何时抓空或滑落。

小样本用于检查迁移后的代码实际运行情况，不能代替完整 50 次成功率。代码与受保护源文件的校验均未变化，视觉工作进程已关闭。后续若要提高成功率，仍需核对真实抓取状态与抓后定位；本轮没有把已去掉的药瓶专用接管检查加回来。
