# 身份证据与局部空域核验：四任务配对复验

## 实现与边界

新增 `evidence_ranked_cad` 与 `verify_scene_structure` 两个独立开关，默认关闭，未替换既有任务入口或模型。查询和目标名称不新增任务特例。

身份分数独立于 CAD：正分文字检测且候选主要位于检测框内时，使用检测分数乘以候选/检测框 IoU 的平方根；有显式颜色提示时再乘现有外观分数。没有文字支持不凭 CAD 加分；分数不是概率，框紧凑度也不是身份证明。选取成本为原几何成本加 `1-身份分数`，权重预先固定为 1，单目标排序、拒绝差值和多目标分配使用相同成本。并非真正的语义分类器或纹理识别网络，可能偏向完整框区域，存在误拒/错排风险。

原流程已检查整幅 CAD 轮廓的覆盖与空域，因此不能说新增了此前完全没有的“完整模型核验”。本次强化的是空间局部检查：将 CAD 投影包围范围分成 4×4 区域，每区至少有 40 个非遮挡实测像素才判定；如果某区超过原有 20% 空域比例，否决该 CAD 假设。这样大面积正确表面不能平均掉局部错误。缺深度和更近的遮挡不算支持，也不直接否决隐藏表面。网格不是上盖/底座等语义部件；未实现语义部件划分、显式桌面碰撞或多视角。本规则也可能在配准不准时误拒正确目标，需要全量对照检验。

`audit_candidate_selection` 保存单目标最终候选ID、原几何成本、合成选择成本，以及多目标最佳/接近的替代分配ID。它是事后定位错误的审计，不影响评分或把评测标签反馈给控制。

## 评测协议

脚本 `scripts/replay_vision_evidence_pair.py`。四个任务：open_microwave、open_laptop、rotate_qrcode、pick_dual_bottles，各使用已完成 benchmark 的全部50个有效初始头部RGB-D，总200场。两种配置各推理一次，总400次视觉请求，不执行机器人动作。

对照组是当前代码、严格语义支持+可见表面补全+颜色核验；试验组仅额外开启上述身份排名与局部空域检查。两组均不启用主体断点补全，避免混入别的改动。历史归档结果另列，不作为本次单因素对照。两组使用相同按任务/seed哈希得到的随机种子，但不保证GPU运算逐位确定。

双方案预测均保存、哈希锁定后，才读取同帧独立分割标签。沿用目标像素占比≥80%、交集≥20像素及可见中心误差≤2cm的口径；可交换目标按原CAD+外观等价组做一对一评分。标签和等价身份审计不发送给视觉worker。记录原成功退化、失败恢复与各目标结果，而非仅选失败场。源码快照和输入哈希保存在新目录。

结果根目录：`results/vision_evidence_pair_200_20261112_v1/<task>/report.json`。每任务一个用户systemd服务，GPU0–3分别负责微波炉、笔记本、二维码、双瓶；同卡两组worker顺序请求，模型常驻。空间不足8GiB则停止，保留已有结果，不删除旧文件。若进程异常，以实际进程和report状态共同判断，不把残留running字段当作仍在运行。

## 审计异常修复

首批正式运行中，笔记本、微波炉、二维码遇到 `float(None)`；未完成的首批结果不作为最终成功率。原因是单目标审计读取 `_prepare_query` 保存的可变候选组，而最终 `choose` 重核验可能已将其中记录改为拒绝、成本置空。并非把 None 当作零的数值问题。

修复：`_select` 在最终有效候选组建立后立即生成纯数值/ID快照，所有提前返回先清空快照；单目标观测只读取该最终快照。不修改身份分数、几何门槛或候选选择规则，不给无成本记录伪造分数。多目标原分配审计逻辑不变。

新增4个回归实例：两种身份排名配置下的失效准备候选、跨帧拒绝清空旧审计、审计开关不改变选择。相关13项测试通过；最终全量结果见 `results/vision_evidence_selection_audit_fix_tests_20261112_v1.log`。

修复前仍运行的旧双瓶服务已停止，原结果目录保留，未将修复代码混入旧批次。新四任务配对复验使用 `results/vision_evidence_pair_200_20261112_v2`，服务名后缀 `20261112-v2`。先导使用此前首帧崩溃的笔记本图像，结果单独保存到 `results/vision_evidence_pair_audit_fix_smoke_20261112_v1`。
