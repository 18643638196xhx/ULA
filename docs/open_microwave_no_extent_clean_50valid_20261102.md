# 微波炉 clean：动态排序与取消固定尺寸门槛

## 测试方案

沿用上一批随机场景中完整成功 34/50（68%）的方案，只将场景配置切换到官方 `demo_clean`。不改感知、动态接近排序、规划预算、VLA 闭爪接管或开门策略，也不重新调整任何控制阈值。仍不额外试抬。

抓后门板跟踪取消固定的 8–90 cm 宽高门槛，其余深度点数、平面支持、二维分布、视觉门轴一致性、相对可见面积和正向开门进度检查保留。初始定位尺寸检查仍保留。

clean 不添加杂物，不随机背景、光照、桌面高度或头部相机位置。任务本身仍会在两个微波炉型号中选择，并在任务规定范围内改变初始位置。clean 不是固定同一模型和同一摆放重复 50 次，也不是将物体真值交给控制器。

相同 seed 在 clean 与 randomized 配置下不保证物体型号、位置和 VLA 采样轨迹完全相同，因此两批是场景配置层面的比较，不作为逐动作、逐物体位置严格配对实验。

## 评测口径

从 seed 0 连续尝试，目标为 50 个成功初始化的场景。初始化拒绝单独记录并补足；方法执行失败计入这 50 次。完整成功要求流程正常完成且官方评分通过；同时报告官方评分成功率。

完成时间为包含环境设置、感知、规划、执行、最终评价和保存的墙钟时间。仅成功样本取均值，剔除首个有效场景；成功率不剔除首轮。模型与视觉 worker 整批复用，不逐轮重载。

控制阶段不读物体位姿、门关节或接触真值；机器人模型、相机标定与机器人自身状态仍需已知。只在控制结束后读取官方评分和门关节诊断，不再回传控制。固定指令为 `Open the microwave.`，不是官方完整指令分布测试。

GPU 7 运行主进程，GPU 6 运行视觉，均为共享 GPU，无算力隔离，沿用 JAX platform allocator。

## 启动

```bash
cd /data1/xuhuixin/ula
GPU=7 XLA_PYTHON_CLIENT_ALLOCATOR=platform \
MAX_JOBS=2 OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
bash scripts/run_open_microwave_no_extent_clean.sh \
  --mode hybrid --episodes 50 --seed 0 --vision-gpu 6 \
  --approach-clearance 0.025 --approach-gripper 0.45 \
  --max-vla-steps 100 --target-angle-deg 70 \
  --output /data1/xuhuixin/ula/results/microwave_no_extent_clean_50valid_seed0_20261102_v1 \
  > /data1/xuhuixin/ula/results/microwave_no_extent_clean_50valid_seed0_20261102_v1.launcher.log 2>&1
```

复现请另选空目录。没有覆盖旧实验或改写原随机入口、原控制器与其他任务代码。根报告保存实际 `demo_clean` 配置、有效分母、每轮记录、源码校验及进程关闭状态；一些沿用的内部键仍叫 `randomized_sources_*`，该键名不表示实际使用随机场景，实际以 `task_config` 和 `effective_domain_randomization` 为准。

## 结果

已结束，`run_status=finished`、`completed_valid_episodes=50`。连续 seeds **0–49** 全部正常初始化，50 次原始尝试即得到 50 个有效场景，没有初始化拒绝，也没有补种子。

| 指标 | 上一批 randomized | 本批 clean |
| --- | --- | --- |
| 完整流程成功率 | 68%（34/50） | **76%（38/50）** |
| RoboTwin 官方评分成功率 | 72%（36/50） | **100%（50/50）** |
| 成功完成平均时间，不含首个有效场景 | 11.647 s，33 个成功样本 | **10.465 s，38 个成功样本** |
| 初始化拒绝 | 11 次，排除并补足 | **0** |
| 初始视觉定位失败 | 14 | **0** |
| 开门阶段完整失败 | 2 | **12** |

本批首个有效场景 seed 0 在流程末段失败，因此剔除它之后，38 个成功样本仍全部用于成功完成均时；模型已经在首轮加载和执行，不是把首次成功的冷启动计入稳态。成功率仍保留 seed 0。两批成功样本、目标实例与物体初始位置分布并不逐一对应，完成均时不是严格配对提速结论。

335 项 CPU 回归通过。报告实际配置为 `demo_clean`，`random_background=false`、`cluttered_table=false`、`random_light=false`、`random_table_height=0`、`random_head_camera_dis=0`、`clean_background_rate=1`，控制使用的 `depth=true` 保留。50 次初始视觉 worker 请求全部正常返回；所有 50 个场景都完成传统接近并进入 VLA 和传统开门。

## 为什么官方评分为 100%，完整流程却是 76%

完整成功要求“控制器按自己的终点与验证规则正常结束，并通过官方评分”。官方评分只按结束时门关节是否达到任务规定开度判定。控制器目标仍为视觉约 70°（保留 1° 收敛范围），且每个动作后都要有通过门板跟踪与正向进度检查的观测；它和官方评分不是同一条规则。

本批 12 次完整失败全部在传统开门后的验证阶段，最终官方评分均为通过，没有初始定位、接近路径、VLA 接管或初始化失败。它们不能表述为“12 次没有拉开门”；也不能仅凭官方通过就说全部为视觉误判，因为控制器还有更严格的开度和每步进度要求。

| 流程停止类型 | 数量 | seed | 具体记录 |
| --- | --- | --- | --- |
| 测得角度增量为负 | 6 | 0、2、9、10、15、36 | 当前门面仍能拟合，但两次观测均未得到正向开门增量 |
| 当前平面跟踪未通过 | 5 | 1、21、30、43、46 | 头部与腕部均未返回通过保留判据的当前门面 |
| 正增量小于门槛 | 1 | 47 | 测得约 0.380°／0.353°，低于保留的 0.4° 下限 |

失败前最后通过的视觉门角约为 63.18°–68.94°。seed 47 新测角度约 68.994°／68.967°，也没有进入既定的 69° 终点范围；本批未临时四舍五入为到位、修改成功定义或放宽增量门槛。

负增量可能涉及实际门运动或平面估计变化。控制结束后读取的单帧门关节不能重建前一步真实转角，本批没有足够逐步真值证明全部是门回弹或全部是视觉跳变，因此只按直接触发判据分类，不将其统一归因为抓取滑脱。

## 一致性与结论

`randomized_sources_unchanged=true`、`placement_files_unchanged_during_run=true`；逐一读取上一批记录的所有原有文件并比较哈希，无变化。视觉进程整批启动一次，最终 `closed=true`、`running=false`；主进程已退出，退出码 1 表示存在完整失败轮次，并非未跑满 50 次。

结论：当前方案在本批 clean 场景中，50 次均达到官方开门要求，初始视觉也全部可用；完整流程为 38/50，剩余问题集中在开门收尾观测与进度判据。相较 randomized，本批没有初始识别失败，但有更多末段完整停止；两批实例及轨迹不同，不将这种数量变化简单解释成单一随机化因素的因果效应。本批未继续修改任何判据。
