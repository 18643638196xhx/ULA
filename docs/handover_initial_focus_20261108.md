# handover_block 初始定位改进

## 问题证据

上一轮完整随机任务的50个有效场景中，27次输出红块定位，23次没有输出。蓝色平台在这批中均有输出。检查保存的RGB-D与拒绝日志发现两类主要问题：

1. 方块顶部可能出画面，旧方法把最高可见侧面当成顶面，再要求完整方形顶面，因而误拒绝。最高可见点不一定是真正的物体顶部。
2. 红色像素区域在图像中相连，不代表其深度来自同一个物体。边缘深度与背景表面混入后，量出的跨度可超过20–30 cm；旧方法在SAM分割前就用这些跨度拒绝了候选。

## 修改范围与方法

仅修改 handover 初始视觉入口与几何辅助模块；杯子、药瓶、微波炉感知入口、两侧pi0.5模型、后续运动和释放门槛不变。

- 在RGB-D红色候选上腐蚀一个边缘像素，减少轮廓处混合深度。
- 用3 mm体素、12 mm邻接的三维连通分组分开实际不相连的表面，不依赖机器人/目标身份掩码。
- 在每团三维点对应的图像区域上计算语义证据。方块完整几何验收移到SAM分割之后，不再以不完整顶面拒绝分割机会。
- 分割后再次清理边界与三维连通部分，要求与原候选重叠相容，再计算位姿。
- 保留能直接确定顶面的旧几何方法。顶面不完整时，利用可见侧面法向和宽度、相机位置、视觉桌面高度、已知方块尺寸进行有条件推断。
- 侧面法向提供朝向初值，避免截断轮廓的最小外接矩形被斜对角方向误导。
- 侧面过窄、点太少、相机可见性不一致、表面误差过大或存在不同隐藏中心解时仍拒绝。

此处仍明确依赖已知6×6×20 cm尺寸与“初始直立放在水平桌上”的假设；不声称适用于任意未知物体。隐藏顶端和中心是几何推断，不是相机测到了被遮挡表面。

## 验证

旧50场深度回放中，每场均存在一个通过几何检查的候选，未出现多个通过候选。这只是几何诊断，尚未计入语义、SAM、独立身份或真实位置核验，不能当作100%定位成功率。

完整软件回归日志：`results/handover_initial_focus_tests_20261108_v1.log`。

下一步是50个有效随机场景的初始感知评测，固定从seed40000开始，与上一批作工程对照。机器人不执行接近、抓取、试抬、交接或放置，不加载VLA。

预测文件保存之后，才读取仿真标签/位姿进行独立身份、位置及方形截面对称朝向核验。这些核验结果不回传候选选择或任何控制。

```bash
cd /data1/xuhuixin/ula
GPU=0 HANDOVER_VISION_GPU=1 bash scripts/run_handover_initial_randomized.sh \
  --episodes 50 --seed 40000 \
  --output /data1/xuhuixin/ula/results/handover_initial_focus_50valid_seed40000_20261108_v1 \
  --detach
```

最终区分：有输出、身份正确、两目标位置误差均不超过2 cm、朝向误差mod90°不超过10°。场景初始化失败另计，不从有效场景中删去感知失败。此为已分析场景回归，不是未见场景泛化证明。

## 第一轮独立核验及第二版修正

第一轮50场已结束，484项测试前的该版本完整记录保存在v1目录：红块49次有输出，平台50次有输出，两目标身份/位置/朝向核验通过48次。seed40023把红色瓶身认成了方块；seed40054的多个矮小红色候选占用了有限SAM尝试机会，真实长方块没有被处理。没有把“有几何候选”当成正确识别。

第二版增加两项与seed无关的检查：

- 在SAM前仅做宽松的紧凑长物体跨度筛选，剔除明显矮小的红色部件，避免其占满候选预算。不要求完整顶面。
- 在拟合后检查已知长方体平面一致性，至少85%的点需要在配置的1.5 mm表面公差内，拒绝能勉强贴近长方体的弯曲瓶身。该公差是针对当前深度输入的显式工程参数，不能声称可原样迁移到噪声更大的实机传感器。

第二版完整回归测试484项通过，包括圆柱曲面拒绝、局部侧面信息不足时拒绝、顶部裁切以及三维分组。使用新目录重跑同一批50场，代码在评测期间冻结：

```bash
cd /data1/xuhuixin/ula
GPU=0 HANDOVER_VISION_GPU=1 bash scripts/run_handover_initial_randomized.sh \
  --episodes 50 --seed 40000 \
  --output /data1/xuhuixin/ula/results/handover_initial_focus_50valid_seed40000_20261108_v2 \
  --detach
```

最终结果以v2报告为准，不据第一轮结果推算完整任务成功率。预测阶段仍只读取RGB-D和标定；仿真真值仅在预测文件保存后独立核验，不回传算法。

这是同一批已分析场景的定位专项回归结果，既不是未见场景泛化结论，也不是完整操作成功率。后续抓取、交接和放置尚未用新初始定位版本重新评测。

## 接回完整五阶段的评测

用户确认后，已用新定位接回完整流程：传统接近 → 左手pi0.5抓取 → 传统搬运到交接区 → 右手pi0.5接取及左手释放 → 历史视觉与通用约束反馈的传统放置。

固定从seed40000开始，评测50个有效随机场景；初始化失败另计。左右手各使用原10000步检查点，保留各200步模型动作预算、不试抬、原运动与释放条件。运行前核对初始定位专项的全部源文件指纹一致。推理和控制不读取物体真值授权阶段切换，真值仅作独立阶段审计和最终评分。

```bash
cd /data1/xuhuixin/ula
GPU=0 HANDOVER_VISION_GPU=1 bash scripts/eval_pi05_handover_constraint.sh \

  --output /data1/xuhuixin/ula/results/pi05_constraint_initialfocus_full_50valid_seed40000_20261108_v1 \
  --detach
```

这是完整任务评测，与上文零机器人动作的定位专项不同。旧定位加通用纠偏版本的参考结果为完整成功18/50、交接后放置18/23；新结果必须由本次完整执行得到，不能用定位通过率推算。仍是同一批已分析种子的工程对比，不能视作未见场景泛化证明。最终以新输出目录的report.json为准。
