# 杯子任务随机场景评测：50 轮

## 评测对象

用户确认任务为 `place_empty_cup`，不是药瓶。复用既有杯子点云视觉 ULA：传统点云接近 → VLA 闭爪候选 → 传统试抬与视觉跟随确认 → 点云配准传统放置。不使用杯子 CAD/FoundationPose，不读取在线杯子/杯垫位姿或物理接触真值；最终评分可以读取仿真真值。药瓶“不试抬”的设置不移植到这个杯子历史基线。

原始控制源文件 `scripts/run_place_empty_cup.py` 保持不变，SHA-256 为 `e48f6bc4e25da2b46f619c79705b647655c814c25908e6f660c22e18a272a090`，与既有 clean 49/50 批次一致。新增独立入口只切换场景配置、限制共享显存并记录运行元数据，不改变控制门槛。

## 随机化边界

从本地官方 `demo_randomized.yml` 读取 `domain_randomization`，真正传入环境创建：随机背景纹理、杂物、光照，桌面高度参数 0.03 m（本地实现为向下随机最多 3 cm），干净背景比例 0.02，极端随机光照比例 0.02，相机距离随机量仍为 0。

杯子仍为固定 `021_cup/base0`，杯垫仍为固定任务模型，初始杯子/杯垫位置随机。固定左臂、默认光栅渲染、固定原任务句子，以便对应 clean 基线。虽然场景 YAML 的 `eval_instruction` 为 unseen，本入口没有采样未见语言句子；**这是随机场景对照，不是完整官方 benchmark，不是新杯子模型泛化或纯抓取评测**。

当前传统规划仍保留配置的桌面碰撞盒；没有新增从杂物点云重建完整碰撞场景。若因这一限制失败，需要如实计入，不在评测中途修控制器。杯子图像颜色、配准质量和可见范围也可能受随机化影响。

## 设置

连续原始种子 0–49，50 轮，不使用 accepted-seed 缓存、不筛种子、不替换失败。使用原 WorldLA 100k 权重、tail_blend 0.25、推理种子 20260901、最多 500 个 VLA 动作，共享 GPU7。JAX 分配比例 0.40，主进程 Torch 0.08，视觉 Torch 0.10；这些不是整个程序的硬显存隔离。

```bash
cd /data1/xuhuixin/ula
GPU=7 bash scripts/run_place_empty_cup_randomized.sh \
  --mode hybrid --arm left --approach-mode pointcloud \
  --pointcloud-multiview --pointcloud-reobserve \
  --grasp-retries 1 --grasp-stall-steps 120 \
  --registration-max-rmse 0.012 --registration-max-tilt 35 \
  --grasp-handoff visual-trial-lift --contact-gripper-threshold 0.05 \
  --episodes 50 --seed 0 --max-vla-steps 500 \
  --output /data1/xuhuixin/ula/results/cup_randomized_50eps_seed0_20261101_v1
```

输出同名 `.log`；原始统计在目录内 `report.json`。每轮保存初始/交接/最终多相机图片及过程审计。报告逐次写入正确的 `task_config=demo_randomized`、有效随机化字典、保护文件和配置指纹，不保留原入口写死的 clean 标签。

264 项全量回归通过。运行期间冻结代码和阈值。成功率分母为全部 50 轮；时间排除第一轮、只对成功轮求平均，并另报全部尝试时间。设置失败也保留并单独统计；若整批因外部运行错误未完成，不将部分结果当作最终 50 轮结果。

对照 clean 来源：`results/visual_trial_50eps_20261024_v1/report.json`，49/50，剔除首轮后的成功均时 6.120 s（48 个成功样本）。仅为历史固定任务批次对照，随机场景的同 seed 不保证目标物体位置与 clean 一模一样，也不据一批结果断言显著差异。

## 最终结果

50/50 个原始连续种子已全部尝试，`run_status=finished`，保护文件指纹一致。感知进程仅启动一次、完成后正常关闭；197 次请求中 187 次正常返回，其余请求失败由原有有界重观测逻辑处理。运行期间没有修改算法或阈值。

| 口径 | 结果 |
| --- | --- |
| 全部原始 50 次尝试的完整任务成功率 | **52%（26/50）** |
| 场景成功初始化后的条件成功率 | **61.9%（26/42）** |
| 场景初始化失败 | 8/50，均为随机杂物不稳定 |
| 排除第一轮后的成功完成均时 | **7.911 s（25 轮）** |
| 排除第一轮后的全部尝试均时 | 6.394 s（49 轮，包含失败和初始化失败） |
| 传统接近到位 | 37/50 |
| 视觉试抬交接记录 | 34/50 |

第一轮 seed 0 成功，因此成功时间统计排除该轮后为 25 个样本。失败较早的轮次耗时短，不能把“全部尝试均时”当作完成任务更快的证据。GPU 分配比例与历史基线不同且共享负载不受控，耗时仅为本批实测，不作稳定加速/减速归因。

### 结论和边界

相同点云视觉 ULA 在历史 clean 批次为 49/50，本批随机场景为 26/50；即使单列 8 次初始化失败，在 42 个已初始化场景中也只有 26 次完成。退化不仅发生在 VLA 抓取，还涉及初始视觉、传统接近、试抬视觉确认、放置规划和最终位置。

这些阶段名是失败定位，不是已经完成根因诊断。不能据此说都是 VLA 模型问题，也不能仅凭随机化配置就断言每一次规划失败都由杂物碰撞造成。控制器仍使用配置的桌面碰撞盒，没有新增杂物几何重建，属于待查的明确限制。

报告正确保存 `task_config=demo_randomized` 和完整有效随机化字典；仍使用固定左臂、固定杯子模型、原固定语言句子和光栅渲染，不是新杯子泛化或官方未见语言协议。原始结果不改写，后续若修复需新开实验目录。
