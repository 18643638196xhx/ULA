# 微波炉开门：问题修复与复测

日期：2026-10-25。仅修改独立微波炉模块，杯子放置任务和原始 `/data2/xuhuixin/tra_pipe` 不变。

## 原来的问题

首次 50 轮使用 seed 0–49，完整成功 13/50（26%），原始 RoboTwin 评分成功 20/50（40%）。完整成功要求：VLA 仅负责靠近和闭爪，传统控制完成首次试拉及后续开门，视觉达到 70° 目标的既定收敛范围，并且原始任务评分通过。

23 轮停在初始感知，14 轮停在传统开门。凹陷门窗和外框不在同一平面，把整个门框区域当成一个平面会失败。连续开门时，旧代码又用上一帧新增的点扩大下一帧搜索区域，逐渐把静止机身和背景带了进来，导致后期跟踪异常。

原结果：`results/microwave_depth_50eps_seed0_20261025_v2/report.json`。首次加载的一轮不计入耗时后，完整成功的 12 轮平均总耗时为 8.862 秒。成功率仍按全部 50 轮计算，不排除第一轮或失败轮。

## 改了什么

初始识别仍先由图像检测定位门区域。若整体平面拟合失败，就在这个区域的真实深度中寻找最多四层竖直平面，分别检查哪一层旁边有可信的突出竖直把手。因此凹陷窗面不会再迫使整个框区域属于同一平面。每层提议至少覆盖原区域有效点的 12%，最终仍要通过平面支持率、尺寸、把手形状和门轴关系检查；不是不加条件地接受小片点云。

跟踪时保存初始测得的门面矩形大小。后续只根据当前深度测得的门面方向和把手位置更新它的位置、朝向，不再一轮一轮扩大。命令预测仅用于限定在哪里寻找；必须从新深度重新测到门面和把手，不能因为机器人执行了动作就认定门也动了。

接近终点从 TCP 距把手 1 cm 调到 2.5 cm。机器人自身的夹爪模型表明，指尖比这里定义的 TCP 更靠前约 3.56 cm；原 1 cm 目标可能让指尖顶住短把手后的门框。这个分析使用的是已知机器人模型，不是微波炉 CAD。实测原失败到位误差约 2 cm，保持同一目标也没有明显改善；调远后灰色型号 seed 5 完整通过。2.5 cm 是当前任务的实验参数，不是对任意夹爪和把手都成立的安全距离。

规划失败时可有限重试，依次尝试正向 8、10、12 cm 接近点，再尝试较小倾角及 ±20° 姿态。只在尚未执行该候选轨迹时更换目标；已经执行但没到位就停止，不继续换姿态试撞。接近后每段移动不超过 2 cm。到位误差仍要求不超过 1.5 cm、10°；少量保持只维持原目标，不发出更深的接近或新的拉门动作。

同一把手的上半段可能亮、下半段可能暗。现在除了比较 RGB 数值，也检查归一化颜色是否接近，允许有限亮度差；仍保留轴线、宽度、突出深度、最小可见高度和近黑色排除等条件。它只是减少同一把手被阴影分成两段时的误拒绝，不等于能够可靠区分所有夹爪与把手。

没有改变开门目标或视觉随动门槛。看不清、未到位或门没有随手运动时仍停止，不松爪，不让 VLA 代为开门，不使用物体姿态、门关节或接触真值救场。

## 开发验证与局限

保存数据的离线回放中，23 个初始失败场景有 21 个保存了可复用检测框，这 21 个通过新几何识别；另外 2 个缺少缓存，不能据此判断是否解决。14 个原开门失败场景可用新区域跟踪重放几何到原停止帧，但其中 4 个最后一步仍未通过运动一致性检查。离线回放不是重新执行任务，不能用来算成功率。

修复版 v5 的 seed 1–8 完整运行成功 7/8。seed 8 原先在接近 70° 时误拒绝同一把手的明暗片段，现已通过。seed 7 在闭爪后仍遮住把手；v6 改用较小的 +10° 倾角也未解决，系统保留停止判定。没有按单一 seed 取消视觉检查。

以上是反复开发用的小样本，不能代替 50 轮结果。仍假设门轴竖直、把手靠近自由边、铰链靠对侧可见边；隐藏铰链没有被直接测量。没有力反馈，规划也没有完整动态门板与机身碰撞模型。真实部署还需校准与接触安全验证。

## 固定版本的 50 轮复测

评测 seed 0–49，不删除失败样本。VLA 预算 100 步、传统目标 70°、每次最多 3°、最大 40 步；接近距离 2.5 cm、初始夹爪命令 0.45。WorldLA 与视觉进程在整批实验内常驻。GPU 7 运行模型/规划/仿真，GPU 0 运行视觉，JAX 分配器预算 45%，主/视觉 PyTorch 各 10%；这些不是硬隔离，不承诺对其他任务没有影响。

```bash
cd /data1/xuhuixin/ula
GPU=7 MICROWAVE_VISION_GPU=0 MAX_JOBS=2 \
  OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  bash scripts/run_open_microwave.sh \
  --mode hybrid --episodes 50 --seed 0 \
  --approach-clearance 0.025 --approach-gripper 0.45 \
  --max-vla-steps 100 --target-angle-deg 70 \
  --output /data1/xuhuixin/ula/results/microwave_repair_50eps_seed0_new
```

本轮实际输出：`results/microwave_repair_50eps_seed0_20261025_v1/report.json`。
代码冻结校验：同级 `microwave_repair_50eps_seed0_20261025_v1.sources.sha256`。
完整日志：同级 `microwave_repair_50eps_seed0_20261025_v1.launcher.log`。

### 补充修复

v1 结束后，确认 seed 17、18 的整片初始区域可拟合，但去除静止面板后仍混有凹陷窗面。原快速路径未在这一步回退到分层识别；现在在快速路径返回前也验证控制器实际使用的门面子集，失败就进入已有分层识别。没有取消最终平面检查。

已新增 CPU 分支回归测试，全部 168 项通过。seed 17–18 的实际任务验证均完整成功：`results/microwave_repair_seed17_18_20261025_v7/report.json`。这项补充发生在 v1 批次结束之后，不能将该批次 80% 当作后续版本的精确成功率。

最终版另行冻结并运行同一组 50 轮，配置与 v1 相同：`results/microwave_repair_50eps_seed0_20261025_v2/report.json`；源码校验和完整日志为同级同名前缀的 `.sources.sha256`、`.launcher.log`。没有用两个专项成功替换 v1 中的失败记录来拼出新成功率。

## 最终版本结果（50/50 已结束）

| 指标 | 原版 | 当前修复版 v2 |
| --- | --- | --- |
| 完整流程成功 | 13/50（26%） | 39/50（78%） |
| 原始任务评分成功 | 20/50（40%） | 44/50（88%） |

成功率按全部 50 轮计算。耗时是从环境设置到最终评价与画面保存的主机墙钟时间，不是纯机械运动时间，不包含每轮记录之后的环境关闭开销。模型/视觉仅在首次使用时加载，第一轮保留在原始记录中，仅从稳态耗时平均中排除。所有尝试（包含失败）排除第一轮后的平均耗时为 8.548 秒。成功耗时的样本集合与原版不同，因此不能仅凭两列平均值断言同一场景变快。

1、30、37、38、44 这五轮虽通过原始评分，但没有完整通过新流程，仍计作失败。没有把“接近 70°”或原始任务评分当作跳过随动检查的理由。两次修复版评测分别得到 80% 和 78%，不能宣称已经稳定达到 80%，更不能说全部问题已解决。

最终 CPU 回归 168 项通过；评测结束后的六个微波炉源码校验全部与启动前一致；四个受保护放置文件前后及原始校验一致；视觉进程启动一次并已正常关闭。最终评测退出码为 1 是入口对存在失败轮的既定返回方式，不是实验只跑了一部分。

后续重点应是提高闭爪/开门时的可观测性、排除分割回退的错误部件，以及让小增量收尾与测量分辨率更匹配。这些尚未实现，也没有通过降低现有成功标准来提前计入改善。
