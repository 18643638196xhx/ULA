# 微波炉：几何候选、关节状态排序与分级规划预算

## 本次改动

上一批直接拉门方案成功完成平均耗时 23.776 s，其中接近 14.340 s、接近路径规划 13.371 s。原实现先按固定顺序试姿态，同一目标最多调用规划器 3 次，每次内部最多 10 轮求解；32 个稳态成功样本中累计有 232 次接近候选规划失败。不能根据这批结果直接把 10° 固定设为其他任务的最优姿态。

本次新增独立分支。初始 RGB-D 感知、VLA 闭爪接管、传统分步开门、视觉检查、成功定义、无额外试抬的流程均保留；只更改传统接近阶段。没有改写原控制器、外部 RoboTwin/规划器文件，也没有修改杯子与药瓶的执行路径。

### 候选怎样生成

目标来自当前视觉测得的门面和把手，以及机器人 EE/TCP 标定变换。沿门面法向附近、满足竖直把手横向夹持要求的姿态范围采样；还加入机器人当前工具朝向在允许范围内的投影。候选数值遍历顺序不作为规划优先级，不读取历史成功率、seed 或模型真值。

此实现仍有明确任务约束：竖直把手、允许的接近俯仰范围、既有安全距离。使用旧候选的 ±20° 范围（5 个等间距角度），保留用户指定的默认俯仰及当前朝向投影；安全距离仍为至少 8、10、12 cm 的原约束。相比原列表，新增同一允许范围内不同距离/角度的组合。它不是不含先验的任意物体抓取生成器。

可复用的是排序与搜索引擎，不是把“竖直把手”的约束原封不动用于所有任务。其他任务需要提供自己的合法目标和姿态约束。

### 候选怎样排序

先复用原机器人规划入口的全部坐标转换，在进入真正求解器前取得标准起始关节状态和目标。此处不执行路径、不读取物体真值，只是避免新代码另写一套容易不一致的坐标变换；当前接入要求进程内 CuRobo，不支持 IPC 规划器时会明确报错。

每个目标使用同一 CuRobo 机器人模型求 IK，最多取 4 个返回解。在有效解中，优先选择关节移动较小、距离关节极限较远的解，再按该分数排序目标。关节差值不绕过硬限位计算。

具体通用评分为：关节变化除以各关节允许跨度后的 L2 范数，加上 `0.1 × (1 − 2 × 最小归一化限位余量)`。0.1 是通用评分权重，不是用微波炉成功角度拟合出的权重。排序不证明轨迹最短，IK 解只是候选排序的提示，后续运动规划会自行求解，不保证使用同一 IK 分支。

IK 成功不代表整条路径可行；快速 IK 没解也不证明物理不可达。没有通过 IK 的候选不进入快速路径搜索，但仍保留在高预算回退中。

### 预算怎样分配

先按上述排序逐个快速规划：每个候选只调用一次，内部最多 2 轮，时间停止条件为 0.5 s。所有快速候选都失败，才逐个启动高预算回退：每个最多 10 轮、10 s；不再对同一个目标外层连续重复 3 次完整调用。

时间条件不是对正在运行的 GPU 优化进行硬抢占，所以单次实际墙钟时间可能超过该值。关节限制、碰撞与轨迹收敛要求没有放宽。碰撞模型仍仅覆盖原机器人自身和配置桌面，并非完整场景障碍地图，不能宣称已保证对微波炉机身和随机杂物无碰撞。

只有完整路径规划成功才执行，并复用原 `move_to` 的末端到位、关节审计和有限端点保持检查；不会用另一条未验证轨迹取代它。接近把手的每段小移动也先快速规划、失败再高预算规划；任何已执行但未到位的动作都停止，不盲目换姿态继续。没有新增试抬或试拉动作。

## 验证和实验设置

7 项新增 CPU 单测覆盖：当前机器人状态变化会改变排序；不绕过关节硬限位；快速候选先全部尝试再高预算搜索；IK 失败可回退；成功后不继续重复；视觉法向影响目标；标准坐标转换复用与原方法异常恢复。全量 328 项回归通过。

接入检查 `microwave_ranked_pilot3_seed0_20261102_v1` 为 1/3 完整成功：seed 1 初始视觉失败；seed 0 接近成功，但开门到最后一次可信约 19.70° 后丢失门板；seed 2 完整成功。seed 2 的接近耗时约 2.137 s（旧批约 17.544 s），其中 IK 筛选约 0.239 s、路径规划约 0.492 s。两次通过初始视觉的场景均按动态分数选到 20°/12 cm，但代码没有为该角度设置优先级。这是小样本接入与开销检查，不是正式成功率，也不据此调整角度优先级。

正式评测冻结同一版算法与配置，`demo_randomized`、固定指令、seed 0 起连续尝试，填满 50 个正常初始化的场景。初始化拒绝单独保存并补足；方法执行失败保留在 50 次分母内。完整成功要求流程完成且官方评分通过，另列官方评分。平均时间取成功样本且剔除首个有效场景。

主进程 GPU 7、视觉 GPU 6，共享 GPU 无算力隔离；与上一批同用 JAX platform allocator。只在控制结束后读取官方评分/门关节用于评价，控制不使用物体真值。

```bash
cd /data1/xuhuixin/ula
GPU=7 XLA_PYTHON_CLIENT_ALLOCATOR=platform \
MAX_JOBS=2 OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
bash scripts/run_open_microwave_ranked_randomized.sh \
  --mode hybrid --episodes 50 --seed 0 --vision-gpu 6 \
  --approach-clearance 0.025 --approach-gripper 0.45 \
  --max-vla-steps 100 --target-angle-deg 70 \
  --output /data1/xuhuixin/ula/results/microwave_ranked_randomized_50valid_seed0_20261102_v1 \
  > /data1/xuhuixin/ula/results/microwave_ranked_randomized_50valid_seed0_20261102_v1.launcher.log 2>&1
```

复现需另选空目录，不覆盖本批输出。根目录 `report.json` 记录有效计数、初始化拒绝、每轮完整结果、候选/IK分数、每次搜索预算和状态、分阶段计时、源码哈希与视觉进程关闭状态。

已结束：`run_status=finished`、`completed_valid_episodes=50`。连续尝试 seeds 0–60，共 61 次原始尝试；11 次初始化拒绝，与上一批完全相同，均排除并补足。拒绝 seeds：10、14、27、31、37、38、39、45、49、53、55。两批正式比较的是同一组 50 个有效场景。

| 指标 | 上一批直接拉门 | 本次动态排序与分级预算 |
| --- | --- | --- |
| 完整流程成功率 | **66%（33/50）** | **52%（26/50）** |
| RoboTwin 官方评分成功率 | 72%（36/50） | 62%（31/50） |

### 相同场景的接近时间

为避免成功集合差异，选择两批都完成接近的共同场景，且排除首个有效 seed 0，共 **35 对样本**；不要求最终任务成功，从而不会把后续开门失败导致的耗时截断误算成接近提速。

| 相同 35 对样本 | 上一批 | 本次 |
| --- | --- | --- |
| 接近总墙钟时间 | **14.567 s** | **2.129 s** |
| 其中完整路径规划 | 13.577 s | **0.674 s** |
| 本次新增 IK 候选筛选 | 无 | **0.326 s** |

接近总时间下降约 85.4%。新计时包含全部候选生成、IK、路径搜索和执行，没有把候选筛选放到计时之外。共享 GPU 没有算力隔离，因此不把精确倍率当作独占硬件性能结论。

36 个通过初始视觉的场景均完成接近，**全部由排序器选到 20°/12 cm，且首次快速路径调用即成功**；接近末端的小段移动也没有触发高预算回退。排除首轮后统计为 35 个，和汇总脚本的计数一致。

这不是把 20° 写成固定优先级，而是本组相近初始机器人状态、目标范围和当前评分共同产生的选择。它也暴露了该评分的局限：关节变化小、限位余量好，不代表后续抓取和视觉跟踪最可靠；本批不构成跨任务泛化验证。

### 成功率为什么不能说改善

上一批 33 个完整成功中，本批保留 26 个，没有新增成功，新增完整失败为 **0、15、30、35、36、40、44**，全部在接近、VLA 闭爪完成后的传统开门阶段停止。

| 新增失败 seed | 最后通过的视觉门角 | 控制结束后的官方评分 |
| --- | --- | --- |
| 0 | 19.70° | 未通过 |
| 15 | 25.33° | 未通过 |
| 30 | 66.69° | 通过 |
| 35 | 19.62° | 未通过 |
| 36 | 22.54° | 未通过 |
| 40 | 65.28° | 通过 |
| 44 | 22.60° | 未通过 |

这些停止的直接原因都是当前头部与腕部门板观测未通过检查；不是路径规划失败，也不是额外试抬失败。0、15、35、36、44 在较早阶段停止，且最终官方评分未过；30、40 已达到官方要求，但流程收尾视觉检查未通过。原来的 5、23、28 仍是完整失败且官方通过，因而本批官方通过比完整成功多 5 次。

仅凭“视觉跟踪拒绝”不能断言夹爪滑脱，当前没有逐帧证据证明这 7 次具有同一种物理原因。新接近目标会改变 VLA 接管状态和后续夹爪/相机遮挡关系；当前评分没有评价这些因素。由于候选组合、排序、搜索预算共同改变，本批也不是将退化严格归因于某一个角度的单因素实验。

14 个初始视觉失败仍为 1、3、4、7、9、18、19、20、24、43、46、50、52、57，均尚未进入 VLA。没有因为接近阶段更快而修复这部分定位问题。

### 一致性与结论

`randomized_sources_unchanged=true`、`placement_files_unchanged_during_run=true`；逐一比较上一批记录的原有源码哈希，无差异。视觉 worker 仅启动一次，结束后 `closed=true`、`running=false`；评测主进程已经退出。退出码 1 表示存在失败轮次，不是批次未完成。

**结论：这个独立分支解决了接近阶段反复规划的主要耗时，但没有得到整体更好的 ULA——完整成功率下降 14 个百分点，官方评分下降 10 个百分点。** 目前保留为实验分支，不替换旧方案。若继续改进，需要让候选评价考虑后续抓取适配和观测可靠性，并进一步核对失败画面；不能把“机械臂更容易到达”直接当成“完整任务更可靠”，也不应为掩盖退化而放宽开门检查。
