# 随机场景杯子：已知 3D 模型方案

## 对照目标

用户要求用 3D 模型再试随机场景 `place_empty_cup`。新建独立入口，不覆盖点云方案、原杯子稳定入口或旧实验。已知模型明确为任务固定的 `021_cup/base0`，来自预先准备的 GLB 和模型元数据，不是实时读取仿真杯子的位姿。

保留最近修复的杯子/垫子选择、静止垫子视觉目标和 VLA 原图输入；不启用开发对照中效果更差的 VLA 背景模糊。仍为 demo_randomized、固定左臂、原固定指令/权重、500 动作预算、连续原始种子，不是官方未见语言采样或未知杯子泛化。

## 流程

1. 从当前 RGB-D 中选择可信蓝杯与圆垫，不因检测最高分就接受杂物。
2. 在选中的杯子深度上运行 FoundationPose，将已知模型匹配到当前可见表面。深度输入不包括分割外的夹爪/背景，不读取仿真像素身份。
3. 检查可见深度到 CAD 表面的中位距离不超过 8 mm、至少 65% 的点在 15 mm 内，且完整 CAD 不低于视觉桌面超过 8 mm。最多检查本次配准前 16 个高分候选；都不可信就停止，不用真值或粗点云中心伪装成精确模型位姿。
4. 将已知抓取接触点按视觉位姿变换，使用左臂接触点 2、10 cm pre-grasp 偏移，传统控制只执行第一段接近，不执行模型生成的抓取/闭爪动作。
5. VLA 接近并闭爪，仍使用原无在线物体真值的视觉试抬交接。试抬验证只用点云/ICP，不要求 FoundationPose 通过，不使用接触信息或真值高度。
6. 抓后重新运行 FoundationPose，计算手与杯子的关系，利用模型杯底功能点规划传统搬运、下降、松爪和撤离。不是用原来的点云近似支撑锚点。

放置复用原 `adapters/placement.py` 的已知模型逻辑：先确认搬运与下降两段可行，再执行；候选为 7 个偏航 × 3 个高度。目标来自本轮初始可信视觉垫子，初始视觉姿态作直立参考。没有把药瓶闭环校正、接触诊断或真值抓稳规则移植进来。

本方案同时改变了接近几何（模型接触标注）和放置几何（模型功能点/位姿），不是“只把 ICP 换成 FoundationPose”的单因素消融。模型表面拟合不证明唯一位姿或实际抓稳；隐藏杯底由模型推算，不是相机直接看到了。

## 实现隔离

- 新增 `adapters/cup_known_model.py`、`scripts/perceive_cup_known_model.py`、独立 Python/shell 评测入口。
- 复用纯几何的表面匹配、中心化帧和桌面检查工具，不修改药瓶控制器。
- 原杯子 driver 保持不变；仅在本次独立进程中替换接近、放置、视觉进程及参考保存接口。共享 shell 增加可选执行入口变量，默认仍运行原随机化入口。
- 报告标记 known model、FoundationPose、接触点和功能点的使用，以及在线位姿来源。原 driver 的 `--approach-mode pointcloud` 在此仅为视觉试抬/调度兼容参数，真实接近/放置实现和报告字段均明确为 known CAD。
- 控制结束后才使用官方评分真值，不在线据此终止 VLA。原随机场景初始化失败保留，不换种子。

277 项全量回归通过，覆盖试抬观察不调用 FoundationPose、背景深度屏蔽、候选桌面约束、全部模型候选拒绝时不返回粗位姿，以及模型放置使用本轮保存的视觉参考。

## 50 轮对照

先导运行正常后，冻结版本和参数，连续原始 seeds 0–49 共 50 轮，输出 `results/cup_known_randomized_50eps_seed0_20261101_v6`，日志为同名 `.log`。与目标修复点云 v4 的场景、左臂、语言、权重、动作预算和视觉试抬门槛一致；模型方案的接近与放置几何不同，保持本方案定义，不在运行中优化参数。

```bash
cd /data1/xuhuixin/ula
GPU=7 bash scripts/run_place_empty_cup_known_randomized.sh \
  --mode hybrid --arm left --approach-mode pointcloud \
  --pointcloud-multiview --pointcloud-reobserve \
  --grasp-retries 1 --grasp-stall-steps 120 \
  --registration-max-rmse 0.012 --registration-max-tilt 35 \
  --grasp-handoff visual-trial-lift --contact-gripper-threshold 0.05 \
  --episodes 50 --seed 0 --max-vla-steps 500 \
  --output /data1/xuhuixin/ula/results/cup_known_randomized_50eps_seed0_20261101_v6
```

所有原始尝试、成功初始化后的条件成功率分开报告。失败不换种子；时间剔除第一轮、仅对成功轮求均值并注明样本数。3D 模型不等于已知场景位姿；配准可能因遮挡或歧义拒绝，结果以该批最终报告为准。

## v6 最终结果

连续 seeds 0–49 全部结束，`run_status=finished`，保护文件一致，视觉工作进程已关闭。模型初始化一次，常驻复用；169 次请求中 163 次正常返回，其余由原有有界流程处理。运行期间无代码、阈值或种子替换。

| 指标 | 目标修复点云 v4 | 已知杯子模型 v6 |
| --- | --- | --- |
| 全部原始 50 次尝试成功率 | 62%（31/50） | **66%（33/50）** |
| 成功初始化场景中的成功率 | 73.8%（31/42） | **78.6%（33/42）** |
| 场景初始化失败 | 8 | 8（同样种子） |
| 传统接近到位 | 41/50 | 41/50 |
| 视觉试抬交接记录 | 34/50 | 37/50 |
| 排除首轮后的成功完成均时 | 8.150 s（30 轮） | **9.354 s（32 轮）** |
| 排除首轮后的全部尝试均时 | 6.765 s（49 轮） | 7.642 s（49 轮） |

两批成功样本不相同。29 个共同成功且不含首轮的种子配对平均耗时为点云 8.114 s、模型 9.328 s；当前模型方案在本批较慢，不能把所有耗时差都精确归因于 FoundationPose，接近目标和实际轨迹也不同。

相对 v4：13、20、43 从失败变为成功，23 从成功变为最终评分失败，净增加 2 次成功。只多 2/50，不作显著性或稳定优势结论，也不能推断 CAD 单因素收益，因为接近姿态和放置几何同时变化。

### 剩余失败

| 阶段 | 次数 | 种子 | 说明 |
| --- | --- | --- | --- |
| 场景初始化不稳定 | 8 | 4、6、12、16、26、31、35、38 | 控制器未开始，不计为抓取失败 |
| 初始目标定位拒绝 | 1 | 19 | 未得到可信的平面圆垫语义候选 |
| 视觉试抬验证失败 | 4 | 9、21、32、48 | 9、48 在试抬前缺少可信杯子基准；21、32 缺少可信跟随证据 |
| 动作完成、最终评分失败 | 4 | 17、22、23、34 | 物体最终位置/高度等评分条件不满足 |

控制结束后评分测得：17 水平误差约 26.2 cm；22 水平约 71.7 cm、竖直约 50.5 cm；23 水平约 8.16 cm、竖直约 3.15 cm；34 水平约 18.7 cm、竖直约 3.35 cm。这些是最终状态诊断，不是控制输入，也不能仅凭终态断言首次失误发生在哪一步。

本批没有以 CAD/深度验证拒绝作为最终错误，但这不意味着模型估计都精确；局部表面一致性不能排除姿态歧义，更不证明夹持稳定。视觉试抬本身仍是启发式证据，传统放置也可能有执行偏差或物体滑落，需另行核查连续过程。

结论：当前已知模型版本比修复点云方案多完成 2 次，耗时增加，随机场景可靠性没有发生质变。它仍依赖正确分割、视觉位姿、抓取关系及真实执行，不是把模型加载进去就获得物体真值；也不能用历史 clean 的真值辅助交接 100% 来替代本批结果。
