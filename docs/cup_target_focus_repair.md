# 随机场景杯子：目标选择修复与可选 VLA 聚焦

## 修什么

v1 随机场景 50 次尝试中成功 26 次，8 次是场景初始化失败。seed 1、11 的初始画面里蓝杯在左下角，但用于接近的分割分别选到了画面右侧的杂物。不能把这些错误仅解释为运动规划不够强。

新增独立的 `FocusedCupPerception`：先剔除视觉桌面高度附近的蓝色纹理，再依据蓝色、紧凑程度、初始直立杯状比例生成候选，以语义置信度和上一次视觉位置关联排序，并用候选内部的实测像素提示 SAM。候选歧义、跳变过大或 SAM 偏离候选则拒绝，不拿最高检测分数直接驱动机械臂。

垫子单独尝试最多三个语义候选，要求实测深度接近视觉桌面、有合理的水平范围与比例；初次可信定位后，在本轮沿用静止垫子视觉目标，避免抓后遮挡让剩余区域中心漂移。每轮重置，不跨轮沿用杯子或垫子位置。

## 新增先验和限制

- 使用“蓝杯、初始直立、紧凑杯状、单个静止圆垫”的任务级先验，不是任意颜色/任意物体的通用定位器。
- 蓝色条件为归一化 B−R > 0.04、B−G > −0.015、最大最小通道差 > 0.06。按视觉桌面以上 5 mm 到 35 cm 的深度筛选，不读取真实桌面偏移。
- 初始候选垂直/最大水平跨度比需在 0.65–1.8，最大跨度不超过 25 cm。候选与上一次视觉位置相距超过 35 cm 则拒绝。这些是新增启发式，不是已知杯子 CAD 尺寸或抓稳证明。
- 不读取仿真杯子/垫子位姿、像素身份、物理接触或固定物体坐标。没有删除物理障碍物，也没有给传统规划器重建全部杂物几何。
- 色偏、完全遮挡、多个相似蓝杯、桌面平面误估或目标被碰动仍可能失败，持续关联不能证明目标身份永远正确。

## 独立 VLA 输入对照

可选的软聚焦保留原图尺寸、像素坐标、视角和状态输入，不裁剪缩放。根据可信杯子点云范围、视觉垫子位置，以及机器人 FK 的末端/TCP，在三个相机中保留目标和双手周围区域，对远处背景作软模糊。杯子在该相机外、或没有可信视觉目标时保留原图，不能创造不存在的观测。它只是输入预处理，不是训练得到的注意力机制，可能因分布变化降低效果，必须单独对照。

`CUP_VLA_FOCUS=0` 只启用目标修复，`CUP_VLA_FOCUS=1` 同时启用软聚焦。新入口为 `scripts/run_place_empty_cup_focused.sh`。原 `run_place_empty_cup.py`、原 RGB-D 感知、药瓶和微波炉代码未修改；随机化入口仅在环境开关开启时使用新路径。

## 验证

272 项全量回归通过。包括蓝色扁杂物拒绝、蓝色桌面在连通前剔除、目标跳变拒绝、视觉桌面高度变化、跨轮重置、聚焦 ROI 像素保持、图像尺寸/原观测不改动和无可信目标不聚焦。

历史 RGB-D 离线回放 seeds 0、1、11、36、48：5/5 返回可信杯子点云，1、11 选中左下角蓝杯而非右侧杂物，36、48 不再将大块蓝色背景作为杯子。输出 `results/cup_target_focus_replay_20261101_v2/report.json`。这只验证这几帧的定位，不是 5 次任务成功。

随后固定连续 seeds 0–3 进行两组完整流程开发对照，每组 4 轮：

- `results/cup_target_focus_pilot4_vla0_20261101_v3`：目标选择修复，VLA 原始 RGB。
- `results/cup_target_focus_pilot4_vla1_20261101_v3`：相同目标修复，VLA 软背景聚焦。

保留 demo_randomized、左臂、原指令/权重、500 动作预算、12 mm / 35° 配准门槛、视觉试抬、一次抓取重试。运行中冻结代码，不换种子。原 v1 相同四种子为 2/4（0、2 成功）。这些种子是开发样本，不代表新的 50 轮成功率；结果以各目录实际报告为准。

### 四轮开发对照结果

| 方法 | 完整任务成功 | 失败种子 |
| --- | --- | --- |
| 原随机化 v1 同样种子 | 2/4 | 1、3 |
| v3 目标选择修复，VLA 原图 | **4/4** | 无 |
| v3 目标选择修复，加 VLA 软聚焦 | **3/4** | 3（流程执行至最终评分但未通过） |

软聚焦组实际调用 16 次、16 次至少一个相机应用聚焦；目标不在该相机内则保留该相机原图。结果不支持将软聚焦默认启用，更不能认为“把背景去掉 VLA 就一定更好”。当前选择只启用目标选择/跟踪修复，VLA 仍使用原始 RGB。两批均完整结束、保护文件一致，常驻感知进程关闭。小样本不作显著性判断。

## 固定 50 轮复测

选用目标选择修复、VLA 原图，保持相同原始连续 seeds 0–49，使用新目录 `results/cup_target_focus_50eps_seed0_20261101_v4`。保留原随机化所有配置、固定左臂、固定语言、原权重与动作/配准门槛；不因为初始化失败而替换种子。运行中冻结源码和阈值，结果以最终报告为准。

```bash
cd /data1/xuhuixin/ula
GPU=7 CUP_VLA_FOCUS=0 bash scripts/run_place_empty_cup_focused.sh \
  --mode hybrid --arm left --approach-mode pointcloud \
  --pointcloud-multiview --pointcloud-reobserve \
  --grasp-retries 1 --grasp-stall-steps 120 \
  --registration-max-rmse 0.012 --registration-max-tilt 35 \
  --grasp-handoff visual-trial-lift --contact-gripper-threshold 0.05 \
  --episodes 50 --seed 0 --max-vla-steps 500 \
  --output /data1/xuhuixin/ula/results/cup_target_focus_50eps_seed0_20261101_v4
```

需分别报告所有原始尝试和成功初始化场景的成功率，初始化失败单列，不计作抓取失败。成功耗时剔除本批首轮，并注明样本数。不能把开发对照的 4/4 加入 50 轮结果。

### v4 最终结果

50/50 次尝试完成，`run_status=finished`，保护文件指纹一致，常驻视觉进程正常关闭。与基线相同的 8 个种子初始化失败；不换种子。VLA 软聚焦关闭，目标选择/关联修复开启。

| 指标 | 原随机化 v1 | 目标修复 v4 |
| --- | --- | --- |
| 全部原始 50 次尝试成功率 | 52%（26/50） | **62%（31/50）** |
| 成功初始化场景中的成功率 | 61.9%（26/42） | **73.8%（31/42）** |
| 传统接近到位 | 37/50 | 41/50 |
| 视觉试抬交接记录 | 34/50 | 34/50 |
| 剔除首轮后的成功均时 | 7.911 s（25 轮） | 8.150 s（30 轮） |
| 剔除首轮后的全部尝试均时 | 6.394 s（49 轮） | 6.765 s（49 轮） |

两批成功集合不同，新增成功样本也可能更难，不能直接把各批成功均时差归因于修复开销。22 个共同成功且不含首轮的种子配对平均为 8.022 s、8.056 s；共享 GPU 单批时间不足以判断稳定性能差异。

逐种子改善：**1、3、10、11、14、33、36、44** 从失败变成功。退化：**13、20、21** 从成功变为视觉试抬确认拒绝。净增加 5 次成功，不把全部变化都视为单一模块的确定因果效果。

原目标选择典型失败的 1、11、36 本批均完整成功。48 不再卡在初始分割，已接近并进入抓取后验证，但视觉试抬未通过；初始目标修复不等于整任务已修复。

剩余 19 次未完成：

| 阶段 | 次数 | 种子 |
| --- | --- | --- |
| 随机杂物不稳定、初始化失败 | 8 | 4、6、12、16、26、31、35、38 |
| 初始杯子定位不可信 | 1 | 19 |
| 视觉试抬确认失败 | 7 | 13、20、21、22、32、34、48 |
| 搬运/下降规划无解 | 1 | 9 |
| 动作完成、官方最终评分不通过 | 2 | 17、43 |

视觉试抬拒绝只是缺少可信的杯子/手跟随证据，不能在未检查连续图像和配准前一概说是空抓或 VLA 失败。本批没有放宽门槛或跳过该检查。场景初始化错误也未修改为成功，仍单列。

结论：通过仅关注正确杯子/垫子的感知候选与持续关联，随机场景完整任务成功率有实测提升，但还没有恢复 clean 历史批次 98%，也没有解决所有失败。直接对 VLA 输入模糊背景未获开发样本支持，保持关闭；不能用本次结果宣称裁图或去背景对 VLA 普遍有效。仍是固定蓝杯/圆垫、固定左臂、固定语言的开发对照，不是未知对象或完整官方未见语言 benchmark。
