# handover_block：RGB-D 全臂避障实验入口

本次针对的是：右手已经接到红块，但放置过程中手臂被桌面杂物挡住，实际关节没有到达目标。保留原有到位检查，不通过放宽误差门槛掩盖碰撞。

## 改了什么

新增独立入口 `scripts/eval_pi05_handover_rgbd_obstacles.sh`，不替换现有评测脚本，也不修改杯子、微波炉、药瓶的控制流程。左手接近、两个 pi0.5 阶段和中间搬运仍沿用原流程；新避障规划目前只用于右手传统放置阶段。

场景初始时，用头部和两路腕部 RGB-D 保存周围表面。每次放置观测后再更新一次：看到新的表面就加入；旧表面只有在新的有效深度明确显示那里已空出来时才清除。被手臂挡住不等于障碍消失，因此不直接清空被遮挡的部分。

如果原场景已启用并标定前视相机，也将这一路 RGB-D 纳入地图，帮助核验被手臂遮挡的区域；不额外创建相机，也不改变 pi0.5 的三个图像输入。

障碍表面以 1 cm 体素表示，转换成封闭表面网格交给 CuRobo。桌面高度和可见范围从深度图估计，不读取桌子模型的位置或尺寸。红块仍使用本任务已声明的 6×6×20 cm 几何先验及视觉跟踪结果，从静态地图中排除；这不代表已经对搬运物体建立了完整的碰撞包络。

只有成功得到抓后视觉拟合，才将当前观测加入背景地图。不能先按交接时的刚性预测删除红块、再把剩下的点存成障碍：预测有偏差时，会把红块自身存成以后难以清除的遮挡残影。操纵目标在松爪及受控撤离期间仍不当作周围杂物；否则会把必经的接触切换当成非法起点。本适配器不声称已完成目标物体自身的全接触碰撞验证。

不能把图像里的机器人也当成桌面障碍。自体过滤使用已知机器人 URDF、基座标定和实测关节角计算各部件的位置，不读仿真像素身份标签。视觉外壳和物理碰撞模型并不完全一样，因此图像过滤还使用机器人自身的视觉外形；不能只用简化的相机碰撞盒来删除相机外壳像素。

放置时，把静止左臂的已知碰撞几何也加入右臂规划环境。RGB-D 网格与目标末端位姿采用相同的基座变换和 ALOHA 标定补偿。规划使用覆盖右臂各连杆的 CuRobo 碰撞球模型，而不是只检查夹爪末端。返回路径后，包含实测起点、所有插值点并补齐大于 0.01 rad 的关节间隔，重新检查全臂约束，通过后才交给执行层。

放置结束或异常退出后恢复原规划器，防止当前场景的障碍图影响下一轮或其他入口。地图和路径检查失败时停止，不回退到仅有桌面的旧地图。

注意本地 CuRobo 的 Warp 网格缓存按名称复用几何。动态地图不能只调用 `update_world`：每次替换几何前要先同步 GPU、清理旧世界网格缓存，再装入新世界；预分配的碰撞张量仍保留，避免破坏 CUDA graph 引用。体素网格共享顶点也必须合并，不能把彼此不连通的三角片直接当作闭合网格。

另一个需要同步的量是手指：原 CuRobo 配置把两根手指固定在张开状态，不能拿这个外形检查已经闭爪的机械手。新入口在每次规划前，用实测的手指关节位置更新碰撞模型；不是把闭爪命令 0 当成实际手指关节角，也不是删除附近障碍来放行。

## 没改什么

没有修改两个 pi0.5 权重或动作预算，没有增加试抬，没有降低视觉释放条件，也没有放宽末端或实际关节到位门槛。规划搜索容量改为 4 个轨迹种子和 4 个图搜索种子，属于新规划器配置，并非声称所有参数均未改变。

新增障碍模块不接受物体真值位姿、物理接触、仿真分割标签或任务评分。原评测框架仍保留独立评分/诊断日志；这些结果不用于选择运动或决定释放。

## 验证顺序

先调试 seed 40004，再回归原来的 8 个碰撞失败样本：40004、40007、40011、40044、40046、40049、40051、40053。它们是有针对性的旧失败样本，不能把通过比例当成随机 50 次的整体成功率。

```bash
cd /data1/xuhuixin/ula
GPU=0 HANDOVER_VISION_GPU=1 bash scripts/eval_pi05_handover_rgbd_obstacles.sh \
  --seeds 40004 40007 40011 40044 40046 40049 40051 40053 \
  --output /data1/xuhuixin/ula/results/pi05_rgbd_obstacles_selected8_20261109_new_run \
  --detach
```

输出目录须不存在。逐轮 `result.json` 中的 `placement_control.rgbd_obstacles` 记录地图和规划复核；`rgbd_obstacles/scene_*/map_*.npz` 保存视觉体素，`plan_start_*.npz` 保存规划器使用的机器人碰撞球及坐标变换，便于区分自体误报和真实障碍。

## 边界

这是可见表面的避障，不是完整场景重建：没有观测到的背面和深度缺失区域不能保证安全。机器人自体过滤使用凸包和小范围容差，也存在删除紧邻机器人障碍点的风险。CuRobo 碰撞球是几何近似，并非对每一个实体三角面的精确连续碰撞证明；起点已进入障碍、狭窄通道、地图残影或不完整的碰撞包络仍可能导致停止。不能因此删除附近障碍或放宽到位门槛；必须先核对地图与机器人模型。

### 现在可以和不可以得出的结论

可以确认：动态障碍地图确实进入了规划，全臂复核实际执行，手持红块残影造成的 40007 起点拒绝已消除；原来的到位门槛没有放宽。

不能确认：这些碰撞失败已被解决，或整体成功率提高。新的主要终止点是规划没有找到满足当前目标及避障约束的解，而不是执行完后到位误差超标。

对 40011 的失败目标另外做了不执行动作的独立 URDF 运动学求解：不考虑障碍时，可将目标位置误差降至约 3.4e-11 m、姿态误差约 1.5e-9 度。因此至少这例不能简单归为“机械臂够不到”。但这个计算不证明加入障碍后一定存在可行解，也没有被回传控制。

下一步应验证任务允许的目标自由度和绕行目标：不仅对固定手腕姿态做碰撞检查，还应在保持支撑位置、直立条件和到位要求的前提下寻找可行姿态/路径。该目标选择层本轮尚未实现，不应通过降低到位或释放门槛替代。
