# 药瓶放置：已知 3D 模型对照

这是一条独立实验入口，不替换当前点云方案，也不修改杯子、微波炉、官方任务或外部 VLA 的源码。

当前已知模型入口默认启用[快速接近候选搜索](pillbottle_fast_pregrasp.md)。下文 v5–v14 与旧 50 轮结果使用原穷举搜索，复现时请显式传入 `--known-approach-search legacy`；新方法使用 `ranked`。此差异仅影响 `annotated` 接近搜索，不修改放置策略。

后续加入[视觉约束与运输后校正](pillbottle_visual_placement.md)，由 `--known-placement-policy visual` 启用。复现本文旧批次或 v16 时，另需显式传入 `--known-placement-policy legacy`；旧报告与结果不改写。

## “已知”的信息是什么

实验开始前明确指定药瓶型号，默认 `080_pillbottle/base1`。使用该模型的外形、尺寸、预先标注的接近抓取点和瓶底功能点。场景构建器按这一型号生成药瓶；位置仍由官方任务随机生成。控制器不会读取仿真药瓶位置来初始化 FoundationPose，也不会在线读取药瓶编号来挑模型。

这与点云实验的“每轮随机抽取五种药瓶之一”不同。因此即使 seed 相同，也不能把固定 base1 的结果当成与之前混合型号的严格配对比较。比较感知方案时，还需要补一个同样固定型号的点云对照。

## 执行流程

头部相机先识别药瓶和蓝色方垫。GroundingDINO 找大致区域，SAM2 分出表面，FoundationPose 将已知模型与 RGB-D 对齐，估计药瓶的位置和朝向。首帧从零配准，之后优先从上一帧可信的视觉位姿继续跟踪；切换相机时用标定转换坐标，不用机器人运动推定瓶子运动。跟踪不吻合时最多重新全局配准一次，每轮新场景清空历史位姿。

估计结果还要与当前深度表面吻合：中位距离不超过 8 mm，至少 65% 的表面点距模型不超过 15 mm。这个检查只能排除明显不一致，不能保证姿态唯一正确，尤其不能消除对称瓶身的朝向歧义。

当前默认使用模型标注接近：把预先标注的接触点转换到视觉估计的场景中，选择可行的预抓取姿态，在接触点前约 6 cm 停下。这里只执行接近动作，夹住瓶子的局部动作仍由 WorldLA 完成。初始 FoundationPose 模型坐标单独保存，供后续瓶底定位与放置使用。接近轨迹降速，并检查机器人实际关节和末端是否到位。

斜向 RGB-D 接近保留为 `--known-approach diagonal` 消融选项，不是默认方案。实测它虽然让五轮都进入了接管，但部分轮次没有实际夹好瓶子，完整结果更差，已恢复默认标注接近，不能把接管次数增加解释为任务效果提升。

当闭爪指令连续 3 个动作低于 0.05，且 TCP 距当前视觉药瓶范围不超过 1.5 cm，暂停 VLA。按用户要求，当前已知模型分支不再试抬，也不检查瓶子是否上移 3 cm 或是否与手一起移动。短暂等待夹爪实际运动稳定后直接进入传统搬运与放置；这个等待不包含额外抬手动作，也不是抓稳证明。

2026-10-31 起，接管阶段明确使用 `coarse_only` 感知：只做图像分割与当前深度反投影，不调用 FoundationPose，也不要求返回 CAD 位姿。模型配准失败不再阻塞粗接管。若分割触及整幅图像边缘或几何异常，有限次使用初始视觉点云在当前相机中的投影区域与正提示点重新分割，再尝试深度提示；不直接放宽触边、点数或距离门槛。投影只帮助搜索，不把旧点云当成当前观测，不假定瓶子已经跟手移动。

放置前再次视觉估计模型和方垫，不要求瓶底已经离桌；相对初始位置的高度变化只保存作诊断，不决定是否允许放置。用已知瓶底位置、当前视觉位姿和机器人手的位置，计算“手应停在哪里，瓶底才能对准垫子”。以初始视觉朝向作为直立参考，规划搬运和下降两段，均可行才执行。搬运目标高度依次尝试高于最终瓶底目标 5、3、2、8 cm，配合十二个偏航候选：优先小幅旋转，必要时允许 ±90° 或 180°；任务要求瓶子直立放在垫子上，不限制绕竖直轴的朝向。允许 2 cm 的前提是本任务的水平桌面与极薄方垫，没有较高障碍物；不能直接把这个低高度搬运策略迁移到有障碍的场景。两段均降速并检查实际到位，保留 3 mm 释放间隙，之后松爪、撤离。搬运轨迹本身可以上升，但不再有一段单独用于判断抓稳的试抬。

放置定位单独估计头部相机中的方垫，再依次尝试头部和腕部相机的药瓶观测，包括原始框、深度正提示重分割、初始视觉区域投影提示。每个精定位候选均要通过同样的 CAD/深度一致性检查，不能把粗点云范围冒充完整模型位姿。整个重看过程不额外移动机械臂。SAM 的改变提示重分割现已实际执行，不再忽略 `refine_cup` 请求。

执行传统接近前，额外核对规划轨迹是否超出机器人关节模型的实际限位。超限时只读搜索其他接近候选，不先执行不可行目标；运动后仍保留实际关节与末端到位检查。搬运与下降规划也核对关节限位。这种限位检查并不能保证机器人没有接触瓶子或关节必然跟上，不能替代实际到位检查。

### 实测状态交接与边界位置放置

2026-10-31 后续修复：接近时先沿用严格目标关节检查。若该检查失败，但末端仍在原来的 2 cm / 15° 范围内，可以把驱动目标切到当前实测关节并等待稳定。每 20 个物理步检查一次，连续三次关节变化不超过 0.001 rad、相对开始保持时的关节漂移不超过 0.025 rad，且末端始终在原范围内，才允许交给 VLA。最多等待 200 个物理步。持续运动或末端离开范围仍停止。这不是直接跳过到位检查，也没有设置机器人关节位置、改变刚度或试抬物体；后续 VLA 继续以实测状态同步输入。搬运阶段不启用这一交接回退，仍要求严格实际到位。

若所有直立放置候选失败，才尝试绕世界 X 轴 ±5°、±10° 的小倾角。使用预先提供的 CAD 完整顶点，计算相对直立姿态的最低点高度变化，并向上补偿，保持模型最低点间隙不因倾斜而减小。接近机器人工作空间边界时，小倾角可以让手更靠近机器人，而不是强行加高或穿过桌面。放置后仍按原评分检查，不改成功条件；小倾角下松爪后由重力落稳并非完整的实机稳定性保证。

对这种边界位置，撤离沿已实际完成且通过到位检查的下降、搬运轨迹反向执行，位置序列倒序、速度取反。先张开夹爪，再逐段撤离，每段仍检查实际到位。不再重新选择一条虽然规划通过、却可能逼近实际机器人约束的撤离逆解。普通直立方案保留原撤离方式。整个过程没有新增试抬。

本分支不使用 ICP，也不会在 FoundationPose 失败后回退到仿真位姿。姿态估计不可信或机器人未到位时停止，不继续放置、不主动松爪。当前假设闭爪接近候选已经夹住瓶子，因此存在空抓搬运、搬运中滑落的风险，不能把交接成功称作抓稳成功。

共用运行器仍保留名为 `traditional_grasp_verification` 的计时/结果槽，当前该槽仅写入 `skipped=true`、`handoff_authorized=true`，不观测、不规划、不移动机器人；`complete=false`、`lifted_grasp_verified=false` 明确表示没有完成抓稳验证。放置仍须得到闭爪接近候选的授权。

## 真值边界

控制使用的是已知 CAD/标注、RGB-D、相机标定、机器人模型及状态、配置的桌面碰撞盒。CAD 和标注来自仿真资产，属于明确提供的先验，不是未知物体方案。没有读取实时药瓶/方垫位姿、物理接触或机器人像素身份标签来决定动作。在线官方成功检查被禁用；控制停止后，才用仿真真值评分并保存诊断信息。

## 命令

```bash
cd /data1/xuhuixin/ula
GPU=7 bash scripts/run_move_pillbottle_pad_known_model.sh \
  --known-model 1 --episodes 1 --seed 0 \
  --output /data1/xuhuixin/ula/results/pillbottle_known_base1_new
```

输出目录必须为空。保存各阶段三相机画面、RGB-D、模型估计、动作轨迹诊断和最终评分；没有连续视频。首轮包含加载、编译，不用来代表稳定完成时间。小样本试跑不能作为 50 次成功率。
