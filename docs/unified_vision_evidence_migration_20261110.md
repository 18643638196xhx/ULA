# 统一视觉：通用证据与分割恢复迁移

日期：2026-11-10。本次在第一版基础上迁入旧感知中可复用的候选核验、前景提示、局部重分割和点云清理能力，没有为杯子、药瓶分别再写视觉类。旧任务入口、控制器、训练权重和外部项目均未修改。

旧版冻结结果仍保留在 [v1 结果目录](/data1/xuhuixin/ula/results/unified_vision_archives_20261110_v1)。最终代码对应 [migration_v2_release 结果目录](/data1/xuhuixin/ula/results/unified_vision_archives_20261110_migration_v2_release)，没有覆盖旧预测。以下数字均为初始图像定位，不是机器人任务成功率。

## 迁入了什么

统一流程现在是：文字检测生成候选，结合声明的外观和测得的支撑关系检查候选，清理分割点云，再判断结果是否可用。候选仍有歧义、必需几何缺失或分割质量不足时，会尝试局部重新分割，不能仅因“已经算出坐标”就结束。

| 能力 | 当前统一实现 |
| --- | --- |
| 候选核验 | 用同一套颜色证据、显式形状范围及支撑关系检查；未提供的条件不自动假定 |
| 前景正点 | 在当前 RGB-D 的候选区域内选择实际有效的前景像素；有颜色提示时优先使用匹配像素，不读取身份标签 |
| 局部重分割 | 裁出候选附近图像，使用框和正点生成多个 SAM 分割，再按同一套证据筛选 |
| 点云清理 | 按像素邻接和三维连续性剔除小的离散区域；边缘收缩仅在不会吞掉细小结构时用于几何计算 |
| 歧义恢复 | 候选选择失败后也能触发第二轮分割；失败的视角不能被悄悄删除以掩盖当前相机间矛盾 |
| 运行开销控制 | 同一视觉进程整批复用模型；同一帧、同一查询的重分割复用文字检测结果；候选和重试均有上限 |

代码没有按任务名或 seed 分支，也没有调用旧杯子/药瓶检测类处理新请求。新工具位于 [evidence.py](/data1/xuhuixin/ula/adapters/unified_vision/evidence.py)，由同一个 [engine.py](/data1/xuhuixin/ula/adapters/unified_vision/engine.py) 和 [backends.py](/data1/xuhuixin/ula/adapters/unified_vision/backends.py) 调用。

## 接口兼容与可选条件

`observe(frames, queries, episode_id=...)` 的调用签名和观测返回结构不变。`TargetQuery` 末尾新增可选 `hints`，缺省为 `None`，旧调用不填仍然有效；客户端和视觉 worker 使用更新后的同一版本。它是向后兼容的查询扩展，不是声称查询字段逐字节完全未变。

`hints` 支持颜色、是否同时需要多种颜色、颜色是否为明确必需条件、与支撑面的关系、校准的向上方向、可选的直立比例和支撑面内紧凑度。所有目标使用同一套处理代码。

例如：

```python
from adapters.unified_vision import TargetQuery, VisualHints

query = TargetQuery(
    "object", ("pill bottle", "orange cap white pill bottle"),
    hints=VisualHints(
        colors=("orange", "white"), all_colors=True,
        appearance_required=True,
        support_relation="above", up_world=(0, 0, 1),
    ),
)
```

这表示调用方明确告诉模块目标的外观，并声明它应位于近似水平的支撑面上方。向上方向来自坐标标定；支撑面高度仍由当前深度观测估计，不读取仿真桌面高度或目标位置。

本轮杯子颜色只是软证据，药瓶的橙白配色及其蓝垫是显式配置的外观条件。杯子、药瓶的初始直立范围和尺寸条件也列在配置中，不是模型自动学到的。药瓶另增加了与旧前端相同的描述性提示词。这是“代码能力＋查询配置”的迁移，不是仅更换某一个算子的消融。

普通未知物体不填这些条件，就不会被强制认为蓝色、橙白配色、直立或放在水平桌上。没有观测到要求的支撑关系时会拒绝输出，不用预先给定的桌面高度补齐。对于已经抓起、转倒的物体，应由调用方移除只适用于初始场景的直立/支撑条件，不能把初始配置无条件沿用到整条操作流程。

因此，可以复用的是这些计算和核验工具，而不是把“蓝杯”“橙白药瓶”等具体先验当成所有任务的共性。当前尚未自动从任务语言规划这些条件，也没有证明对所有未知物体都能零配置可靠定位。

## 同一批图像重新评测

仍使用杯子 42 张、药瓶 50 张、微波炉 50 张初始头部 RGB-D；杯子原 50 个种子中 8 次初始化失败没有图像，不补生成场景。142 张全部预测保存并关闭 worker 后，才读取独立标签评分。

评分规则未变：区域核验要求目标像素比例至少 80%、与目标重叠至少 20 像素；定位核验还要求当前输出满足查询，并且可见表面范围中心误差不超过 2 cm。这里不测 CAD 原点、隐藏杯底或完整六自由度位姿；严格 IoU 指标仍单独保存。

| 同场景两个目标均通过定位核验 | 迁移前统一版 | 本次迁移版 | 旧任务感知同口径 |
| --- | ---: | ---: | ---: |
| 杯子＋杯垫 | 30/42（71.4%） | 38/42（90.5%） | 38/42（90.5%） |
| 药瓶＋垫子 | 9/50（18.0%） | 28/50（56.0%） | 39/50（78.0%） |

| 单目标定位核验 | 迁移前统一版 | 本次迁移版 |
| --- | ---: | ---: |
| 杯子 | 36/42 | 40/42 |
| 杯垫 | 35/42 | 40/42 |
| 药瓶 | 11/50 | 28/50 |
| 药瓶的垫子 | 38/50 | 50/50 |

杯子联合定位恢复了 seed 5、14、15、36、40、41、46、48，共 8 场；药瓶联合定位新增通过 19 场。两批均没有丢失迁移前联合定位已通过的场景。药瓶 seed 49、54 此前“区域大部分正确但位置偏移”的情况，本轮也通过了位置核验。

药瓶仍未追平旧感知。当前 19 场因候选歧义未输出（1、2、3、4、9、10、16、17、26、28、29、30、36、41、43、45、51、52、53），另 3 场选中了与目标标签不重叠的区域（7、23、31）。有些干扰物也能满足简单配色和几何条件，不能仅靠有这些条件就证明目标身份；本轮没有继续放宽门槛或按 seed 修补。旧药瓶流程还包括已知 CAD 核验，本轮没有迁入 CAD 后端，因此这不是两套实现完全等价的对比。

微波炉主体输出从 36/50 变为 37/50，把手从 15/50 变为 18/50。归档没有独立主体/把手标签，所以这些只表示满足内部要求的输出数量，不能称为正确率。也不能把把手输出增加解释为已经证明开门成功率提高。

## 耗时和验证边界

| 平均定位调用时间，不含首次启动 | 迁移前 | 本次 |
| --- | ---: | ---: |
| 杯子场景 | 0.303 s | 0.666 s |
| 药瓶场景 | 0.297 s | 0.874 s |
| 微波炉场景 | 0.471 s | 0.508 s |

重分割、多个分割候选和药瓶的额外文字提示增加了开销，当前没有宣称同时提速。这些时间含接口通信和文件读写，不是机器人任务时间。整批只加载一次模型，模型加载约 4.678 s。

本次新增 14 项通用证据测试；统一视觉相关共 53 项，项目全量 **581 项通过**。测试覆盖可选字段兼容、任意目标名称、显式外观排错、测得支撑关系、离散深度污染、细结构保护、坐标原点平移不变、歧义后真正重分割、不能删除矛盾视角、有效前景正点和颜色提议必须有语义支持。局部突出结构也不能绕过显式外观条件。测试日志见 [全量回归日志](/data1/xuhuixin/ula/results/unified_vision_migration_all_tests_20261110_release.log)。

实际回放共 142 个请求，无推理异常，单进程已退出；运行期间清单所列代码/配置、传感器输入、保存预测均未变化。没有读取目标真值、仿真身份掩码或接触信息用于预测；独立渲染标签只用于事后评分。

本轮是开发归档上的迁移验证，不是盲测泛化实验；也没有把新模块接入旧任务控制器重新跑完整任务。对称性、遮挡、语义相近干扰物以及局部结构搜索仍有未解决问题。
