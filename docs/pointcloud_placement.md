# 不读取杯子 CAD 的视觉放置

## 实现范围

`--mode hybrid --approach-mode pointcloud` 现在连接完整的三阶段流程：

`点云粗接近 → VLA 抓取 → 抓后点云配准 → 传统搬运、放置、松爪、撤离`

接近和放置不加载 FoundationPose，不读取杯子网格、尺寸、接触点或功能点元数据，
也不读取杯子/杯垫仿真位姿来生成动作目标。原 `annotated / geometry` 的
FoundationPose 放置分支保留，不做隐式回退。

这是一个受限的可运行原型，不是任意未知杯子的通用解决方案：假设杯子初始直立、
静止支撑于水平桌面，物体近似刚性，前后可见表面具有足够重叠。未知外观的检测、
VLA 抓取泛化、透明/反光物体、严重遮挡，都需要另行验证。

## 杯底不可见时如何估计

抓取前保存当前 RGB-D 分割回投的点云，不保存或读取物体 CAD。
从杯子周围背景深度估计水平桌面高度 `z_table`。
定义一个**近似支撑锚点**：

```text
a0 = [抓前可见范围的 X 中心, 抓前可见范围的 Y 中心, z_table]
```

它利用“杯子正放在桌面上”的约束，不把最低可见深度点误当杯底。
但 XY 中心只是可见范围的近似，可能受把手和遮挡影响；它不是重建出的底面中心，
也不是从功能点标注中读取的精确参考点。

抓稳后重新分割、回投，用本轮抓前点云作临时参考，通过多起点、裁剪离群点的
点到点 ICP 估计刚体运动 `T = [R, t]`，再得到：

```text
a_held = R × a0 + t
```

这不是在已知 CAD 坐标系下估计语义 6D 位姿，而是两个观测之间的表面配准。
对称杯子的绕轴旋转可能无法辨认；ICP 的低残差也不能证明配准一定正确。
当前没有纹理特征、多视角融合或独立的语义直立验证。

## 质量门槛

默认对 3 mm 体素降采样后的点云作配准，至少 40 个空间不同的点。
初始偏航为 `0 / −0.3 / +0.3 / −0.6 / +0.6` rad，平移初始化来自点云中位数差，
每次最多 45 步，使用距离最近的 80% 观测点并限制最大对应距离为 3 cm。

候选须同时满足：

- 裁剪后 RMSE ≤8 mm。
- 至少 55% 当前点和 40% 参考点在另一点云 12 mm 范围内。
- 相对初始 +Z 的估计倾斜 ≤25°。

多个候选按残差及重叠度评分选择。门槛是启发式拒绝条件，不是稳定性或安全证明；
未通过会保存诊断并停止，不执行搬运、不松爪，不用 CAD 或真值补救。

## 计算末端放置目标

杯垫目标 `b` 仍由杯垫掩码的有效深度回投、裁剪异常点、取中位数得到。
目标支撑锚点高度为杯垫表面高度加 `--pointcloud-release-gap`，默认 3 mm。
机器人保持刚性夹持，补偿配准测得的相对倾斜，将杯子恢复到抓前的假定直立姿态；
允许有限偏航候选寻找可行关节配置，不是始终维持抓稳时的末端姿态。

设抓稳后的末端旋转、位置为 `R_ee, p_ee`，候选世界偏航为 `Rz`：

```text
D = Rz × inverse(R)
R_goal = D × R_ee
p_goal = b + D × (p_ee − a_held)
```

于是刚性夹持下锚点应落到 `b`，不需要真实物体坐标原点或已标注功能点。
若初始杯子不是直立、发生滑移、锚点中心偏差大、或 ICP 误配准，这个推断就可能失效。

CuRobo 对每个候选先规划上方预放置和下降两段轨迹，两段都成功才开始执行。
候选偏航 `0 / ±0.15 / ±0.30 / ±0.60` rad，上方间距 `5 / 8 / 10` cm。
开始执行后不换候选重试；每段都检查真实机器人末端状态是否在目标的
2 cm / 15° 内，通过才继续，未到位不松爪。然后松爪并向世界 +Z 撤离 5 cm。

目前没有末段视觉闭环、真实接触/力反馈放置，也没有基于杯子点云更新夹持物碰撞模型。
规划器保留原机器人和已知桌面的碰撞配置，不能据此宣称未知障碍避障或实机安全。

## 真值与统计边界

- **仍依赖真值**：VLA 抓稳交接继续读取仿真杯子位姿和接触信息。
- **评测使用真值**：RoboTwin 原任务成功、杯子与杯垫功能点误差。
- **不是物体真值输入**：机器人状态、运动学、相机标定；当前由仿真提供。
- 初始正放在桌面上是显式实验假设，未读取真实物体姿态确认它。
- 场景仍加载物体资产进行渲染/物理；不等于控制器使用它作为几何先验。

因此本改造是“无预备杯子几何模型的目标生成”，不是“全系统无真值”。
同一个杯子的多 seed 成功也不能证明未见杯子的泛化。

`report.placement_mode=pointcloud_registration`。
放置结果记录参考 NPZ、ICP 每个起点的残差/重叠度/倾斜、支撑锚点、候选规划及到位检查。
`complete` 只表示控制序列执行结束；真正任务成功仍由 `success / task_success` 表示。
感知每轮两次请求，共用一套 DINO/SAM2；不缓存旧位姿代替新观测。

## 运行

先检查 GPU 空闲情况，使用新的输出目录。示例 GPU 5 不代表长期保留。

```bash
cd /data1/xuhuixin/ula
OUT="/data1/xuhuixin/ula/results/pointcloud_full_50eps_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$OUT"
nohup env GPU=5 bash scripts/run_place_empty_cup.sh \
  --mode hybrid --approach-mode pointcloud \
  --episodes 50 --seed 0 --max-vla-steps 500 \
  --output "$OUT" > "$OUT/launcher.log" 2>&1 < /dev/null &
echo "PID=$! 输出目录=$OUT"
```

`report.json` 同时统计全批次和排除首轮的成功率、平均尝试耗时、成功轮平均完成时间，
以及传统接近、VLA、传统放置的分段计时。失败不能从成功率分母剔除。
本次改造不自动运行 50 轮；先用单轮和小批实验检查完整分支。
