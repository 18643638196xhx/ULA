# 药瓶：颜色、深度与语义联合识别

## 这次改了什么

原入口对“药瓶”和“蓝色垫子”分别做语义检测，优先选择最高分的框。在随机杂物较多时，最高分不一定对应目标，框也可能包含背景或旁边的瓶子。

新入口保留多个语义候选，同时在实际 RGB-D 中寻找符合外观和几何条件的目标：药瓶采用当前 base1 的橙色瓶盖、白色瓶身线索；垫子采用蓝色、位于桌面附近、近似方形的线索。桌面高度来自深度观测，不是读取仿真桌面坐标。颜色候选必须有匹配的语义证据，不能仅凭颜色通过。

对于药瓶，系统先结合语义框、颜色连通区域与桌面以上的深度生成搜索区域，再给 SAM 一个区域框和区域内真实测得的前景点，分出完整瓶身。输出仍是实际深度点，不是凭颜色补出形状。系统检查可见点数、空间范围、初始直立形状、颜色支持和图像边缘截断，再比较候选；两个不同位置的候选分数太接近时停止，不强行选一个。

抓后可能看不到瓶盖，因此该阶段不强制要求橙色可见；但仍需白色瓶身，以及语义或原目标投影搜索区域的支持。投影区域只是搜索提示，不当作新观测；随后的 CAD 定位仍须通过当前实测深度检查。垫子则对蓝色点逐个连通区域检查桌面高度、实际水平尺寸、近似方形比例和语义重叠，不把不同蓝色物体拼成一个垫子。

## 哪些没有改

整体仍是“传统接近 → VLA 局部抓取 → 传统搬运放置”。没有增加试抬，没有更改接管条件、运动规划、放置策略或 CAD 深度一致性门槛。准备好的 base1 CAD 和标注仍被后端使用，不能把这版称为无模型方案。

新前端不读物体真值位置、机器人像素身份标签或物理接触信息。机器人状态与相机标定沿用原流程。最终 RoboTwin 评分仍是独立评测，不能视为不依赖真值的评分系统。

颜色是明确的任务先验，目前只支持事先配置的 base1 外观。换成其他颜色药瓶，需要重新配置或学习外观，不能直接宣称跨颜色通用。阴影、遮挡、多个相似药瓶和深度缺失仍可能导致拒绝。

## 实现与隔离

- 前端：`adapters/pillbottle_focus/frontend.py`。
- 独立视觉进程：`scripts/perceive_pillbottle_focused.py`。只在该进程内替换原 CAD 后端的前端派发，不修改共享类或原文件。
- 新随机评测入口：`scripts/run_move_pillbottle_pad_focused_randomized.sh`。
- RGB-D 回放：`scripts/replay_pillbottle_focus.py`。

杯子、微波炉、旧药瓶入口和外部传统代码保持不变。旧版随机 50 个有效场景已结束，完整成功 14/50；其保护文件和源码指纹均未变化。该结果是旧版对照，不是新方法成绩。

## 已做验证

CPU 回归共 349 项通过，其中新加 11 项覆盖颜色干扰、白色桌面、深度缺失、瓶盖遮挡、抬高的蓝色杂物、候选歧义和独立 worker 入口。

对旧评测中 seed 0、1、2、3、4、5、6、8 的初始 RGB-D 回放，7/8 通过前端检查；其中 seed 0、1、2、5 原来停在初始接近感知阶段。seed 3 出现两个外观相近的候选，分数接近而被拒绝。这个 7/8 是“程序接受了观测”，不是人工标注的识别准确率，也不是任务成功率。选框保存在回放目录，仍需核对目标身份。

另对 seed 0、1、2、4、6、8 保留完整 CAD 定位，6/6 通过原有位姿与深度一致性检查，未降低阈值。这同样不是完整任务成功率。

回放结果：`results/pillbottle_focus_replay_20261102_v2/report.json`、`results/pillbottle_focus_precise_replay_20261102_v1/report.json`。

三次随机场景完整流程冒烟测试也已结束（seed 0、1、2）：初始识别与接近均通过，但完整任务为 0/3，官方评分也为 0/3。seed 0 在 VLA 预算内没有出现满足接管条件的闭爪候选；seed 1、2 在抓后定位阶段停止，头部 CAD 估计未通过一致性/桌面约束，腕部观测也存在图像边缘截断。这说明初始识别改善并不自动解决接管、抓后定位和放置，不能据回放结果宣称任务成功率提高。样本仅用于检查接口兼容，不代表新的 50 次成功率。

冒烟结果：`results/pillbottle_focus_randomized_smoke3_20261102_v1/report.json`。完整评测前还应优先排查这些后续失败；下面保留的是新入口的启动命令，本轮没有自动启动新的完整 50 次实验。

## 启动新的完整 50 次评测

此命令不覆盖旧结果。初始化失败的场景独立记录，并用后续连续 seed 补足 50 个有效场景。

```bash
cd /data1/xuhuixin/ula
GPU=7 PILLBOTTLE_RANDOM_VISION_GPU=6 \
XLA_PYTHON_CLIENT_ALLOCATOR=platform MAX_JOBS=2 \
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
bash scripts/run_move_pillbottle_pad_focused_randomized.sh \
  --episodes 50 --seed 0 \
  --output /data1/xuhuixin/ula/results/pillbottle_focus_randomized_50valid_seed0_v1 \
  > /data1/xuhuixin/ula/results/pillbottle_focus_randomized_50valid_seed0_v1.launcher.log 2>&1
```

GPU 号应按当时的共享资源调整。平均完成时间应排除首个有效场景的加载影响，并注明只统计成功完成的样本。不要用感知回放通过比例代替完整任务成功率。
