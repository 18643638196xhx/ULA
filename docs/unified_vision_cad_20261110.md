# 统一视觉：在候选选择前加入 CAD 核验

日期：2026-11-10。此次只扩展统一视觉模块，没有修改杯子、药瓶、微波炉、交接任务的旧控制器，也没有改动链接的外部项目或旧评测结果。

## 解决什么问题

原先，检测和分割会找出几个“可能是药瓶”的区域，再按文字、颜色和几何证据选择。若几个区域的分数接近，统一模块会拒绝输出；后面的位姿配准还没有机会执行。

现在，如果调用方提供了目标的 CAD，就先把这个模型分别放到每个候选区域中，尝试调整它的位置和朝向。然后检查：模型能否解释实际看到的表面，投影出的范围是否覆盖候选，模型深度是否与相机测到的深度一致。通过这些检查后，再比较候选，决定输出哪个。

这不是“FoundationPose 返回了一个位姿就算找对”。一个错误物体也可能被勉强配准，因此必须核对实际图像和深度。若没有候选通过，或者多个候选的配合程度仍接近，就继续拒绝输出，不偷偷改回只按检测分数选第一个。

处理顺序为：

```text
RGB-D + 目标描述
        ↓
文字检测 → 分割 → 通用外观/几何检查 → 有限次重新分割
        ↓
未提供 CAD：原来的候选选择
提供了 CAD：逐候选配准 → 点云/投影/深度核验 → 再做歧义判断
        ↓
输出当前观测，或明确说明为什么不输出
```

这里没有按任务名称、目标类别或 seed 写特殊分支。药瓶的模型路径与尺寸只在示例配置中声明。其他目标也可以通过相同接口提供自己的静态模型。

## 核验内容与预算

每个视角最多保留 4 个分割候选；重叠的重复分割会去重。对最终有效候选逐个执行 FoundationPose 注册，每个候选最多检查 8 个姿态假设，不只验证检测分数最高的那个。CAD 的尺寸固定，不允许为了贴合干扰物而任意缩放。

核验采用同一套共享参数，不按 seed 调整：

| 检查 | 当前限制 |
| --- | --- |
| 可见点到 CAD 表面的距离 | 中位数不超过 8 mm；15 mm 内的点至少占 65% |
| CAD 渲染深度与观测深度 | 重合处误差中位数不超过 8 mm；15 mm 内至少占 65% |
| 候选被 CAD 解释的比例 | 至少 65% |
| 预期可见 CAD 被候选覆盖的比例 | 至少 55% |
| CAD 非遮挡、有效可测部分 | 至少占渲染范围的 35%，且至少 40 个重合深度像素 |
| CAD 与实际空区域冲突 | 不超过预期可见部分的 20% |
| 多视角位置关联 | 使用配准后的 CAD 原点，距离不超过 3 cm |
| 多个同等视角支持的候选 | 综合误差差距小于 0.15 时仍判为歧义 |

允许真实遮挡，不要求看见隐藏表面。但不能只靠一个很小的表面贴合，就把大部分不匹配都解释成遮挡。综合误差是点云距离、深度误差、覆盖率等量的组合，不是“目标正确概率”。

多视角先用当前 CAD 配准位置判断是否对应同一个物体。当前视角之间明显矛盾时，不会利用历史位置删除其中一个视角来掩盖矛盾。对称物体的转角仍可能有多解；当前核验不声称解决了全部六自由度歧义。

## 接口与使用

`observe(frames, queries, episode_id=...)` 的签名不变；查询末尾增加可选的 `cad`。不填时仍然执行无 CAD 流程，也不会加载 FoundationPose 权重。返回结构保留原有字段，并在 CAD 调用时提供额外核验信息。

```python
from adapters.unified_vision import TargetQuery, CadModel

query = TargetQuery(
    key="object",
    prompts=("pill bottle",),
    cad=CadModel(
        mesh_path="tra_pipe/RoboTwin/assets/objects/080_pillbottle/visual/base1.glb",
        scale=(0.08, 0.08, 0.08),
    ),
)
```

`scale` 是已知的模型单位转换，不是从图像读到的物体位置。可选的 `mesh_to_object` 只用来固定模型坐标系，不能填入本轮物体真值位姿。

输出的 `geometry.position_world` 仍表示测得的可见表面范围中心，以兼容原先的定位接口和评分口径。CAD 位姿另存为 `geometry.full_object_pose_world`；二者的坐标原点不同，不能直接混用。

完整药瓶＋垫子配置为 [bottle_pad_cad.json](/data1/xuhuixin/ula/configs/unified_vision/bottle_pad_cad.json)。它与原来的无模型配置只有药瓶 `cad` 字段不同；垫子仍用视觉平面定位，没有给垫子增加模型。

对已有 50 张有效药瓶图像进行独立回放的命令如下，输出目录必须是新的：

```bash
cd /data1/xuhuixin/ula
env TMPDIR=/data1/xuhuixin/ula/.runtime/tmp \
  PYTHONDONTWRITEBYTECODE=1 \
  PYTHONPATH=/data1/xuhuixin/ula:/data1/xuhuixin/ula/tra_pipe/RoboTwin \
  OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  external/pi05/.venv/bin/python scripts/evaluate_unified_vision_archives.py \
    --gpu 0 --cohorts bottle --known-cad \
    --output results/unified_vision_cad_bottle50_NEW
```

这只是定位评测，不是完整机器人任务评测。更换目标的 CAD 直接通过查询配置完成；上述离线评测脚本的 `--known-cad` 当前只给已有药瓶归档提供示例模型，不代表视觉模块只支持药瓶。

## 加载与可追溯性

DINO、SAM 复用一个进程。第一次 CAD 请求才加载 FoundationPose，评分网络、精修网络与渲染上下文共享；同一模型在有上限的缓存中复用。候选之间重新注册，不拿上一个候选的位姿当作本候选的结果。初始化失败会记录失败，不对每个候选反复加载。

新增了进程级日志隔离：第三方 Python 日志和底层 C/CUDA 标准输出都进入日志文件，JSON 通信使用单独保留的输出通道，避免原生日志破坏批量请求。

有 CAD 的请求会保存最终候选的真实分割掩码、点云、内外参及逐候选核验结果；通过的候选另外保存所选假设的渲染深度。未选中的候选也保存实际掩码，不用包围框事后冒充分割结果。

评测冻结代码、配置、静态模型及输入哈希。全部预测写完、worker 退出之后，才读取独立标签评分。旧冻结结果保持原样。第一次批量尝试因原生日志污染通信中断，保留在 `results/unified_vision_cad_bottle50_20261110_v1`，不能当成定位结果；修复后使用新的 `v2` 目录。

## 边界

该分支依赖预先提供且尺寸正确的模型。示例使用 RoboTwin 自带的静态药瓶资产，因此不能称为“完全没有模型先验”。预测不读取本轮物体真值位姿、身份掩码、接触信息或预标注抓取点；独立身份标签只在预测结束后用于评分。

CAD 能增加几何约束，但不能保证分清外形相似的两个物体，也不能恢复检测阶段完全漏掉的目标。遮挡、错误分割、深度缺失和对称性仍可能导致拒绝或误选；核验通过也不等于已经可以安全抓取、搬运或释放。
