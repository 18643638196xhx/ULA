# 杯子随机场景：仅抓取前杯子与杯垫识别

## 范围

仅测试 `place_empty_cup` 在 `demo_randomized` 的初始头部相机 RGB-D。连续原始 seeds 0–49，初始化失败单列、不换种子。正常环境复位和稳定性检查完成后，禁止任何接近、抓取、试抬、搬运、放置动作；不构造或加载 WorldLA，不调用任务成功评分，不计算完整任务成功率。

这是新候选感知方法的独立诊断，不是当前生产放置入口的成功率，也没有替换旧杯子、药瓶或微波炉流程。仅使用头部相机，不主动移动相机或机器人，也没有本次加入腕部重试。

## 候选方法

杯子先用原 DINO 检测 `cup . mug .`，最多取 5 个语义框，用 SAM 分割，再通过当前深度检查是否为紧凑、直立的桌上物体。颜色只给排序增加最多 0.10 的辅助分，不是候选产生或接受的硬条件；即使蓝色像素为 0 也可以被接受。保留有限的尺寸、竖直比例和竞争候选拒绝，均为显式启发式，不代表通用未知物体识别。

杯垫复用原语义候选 + 桌面平面/尺寸检查，最多 3 个候选，不因杯子失败而丢掉杯垫结果。杯子和杯垫分别报告有输出、无输出及拒绝原因。不使用杯子 CAD、接触点标注或 FoundationPose，也不根据已知任务左右位置限定检测区域。

## 输入与核验隔离

视觉进程只接受四个输入字段：RGB、深度、相机内参、外参。输入如果带额外的仿真掩码等字段就拒绝。所有识别结果及 `prediction.npz`、`prediction.json` 先写出冻结，再读取同一帧的仿真实体分割，仅事后判断预测区域是否属于目标杯子/杯垫。标签不进入识别，不用于选择候选或重试。

核验指标是预测掩码与目标可见实例掩码的 IoU、目标精确率/召回率，以及预定义的 IoU≥0.5 是否匹配。这个检查是“是否分出了目标可见区域”，不是精确 6D 位姿或隐藏杯底测量，更不是抓取/放置成功证明。正式统计只报告数量，不把“返回了坐标”直接算成“认对”。

常规仿真场景构建/稳定性检查本身使用环境真值，与之前评测一致；此处仅承诺识别输入不使用真值。初始化后，任务动作与 `check_success` 被显式保护，误调用会报错。

## 验证与正式运行

新增 7 项 CPU 检查覆盖偏绿杯子、杯子/杯垫独立失败、瓶状几何拒绝、输入字段隔离、动作禁用和错误物体不能算匹配；全量 **297 项通过**。

先导 `cup_initial_pilot2_seed0_20261101_v1` 两个场景均有杯子/杯垫输出，但独立核验发现 seed 1 把旁边容器当杯子（IoU=0），说明仅统计“有输出”会高估。先导用于检查接线与评分，未将这个错误隐藏、覆盖或算成正确。正式版保持同样识别算法和阈值，仅补充事后核验标注图。

正式目录 `results/cup_initial_randomized_50scenes_seed0_20261101_v2`，完整日志为同名前缀 `.launcher.log`。

```bash
cd /data1/xuhuixin/ula
GPU=7 ULA_CUP_RUNNER=/data1/xuhuixin/ula/scripts/run_cup_initial_randomized.py \
MAX_JOBS=2 OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
bash scripts/run_place_empty_cup_randomized.sh \
  --episodes 50 --seed 0 \
  --output /data1/xuhuixin/ula/results/cup_initial_randomized_50scenes_seed0_20261101_v2
```

使用共享 GPU7：沿用主进程 PyTorch 8%、视觉进程 10% 的分配器预算，不是硬隔离。虽然场景构建保留原规划器初始化以保持随机数和构建路径一致，但没有规划或执行任务动作。没有 VLA 显存开销。

每个正常初始化的场景保存原图、原始 RGB-D、预测掩码、预测审计，以及独立核验掩码。`overlay_head_camera.png` 只画预测；`audit_head_camera.png` 在预测上附加事后判断和黄色目标真值轮廓，不能当成模型输入。杯子预测为青色、杯垫预测为粉色。`contact_sheet_01.png` 等总览按 seed 顺序展示 50 次尝试；初始化失败显示为空白说明，不伪造图片。

## 最终结果：50 个种子已结束

`run_status=finished`，连续 seeds 0–49，42 个正常初始化场景均完成一次独立感知；8 个初始化失败为 4、6、12、16、26、31、35、38，与之前杯子随机场景的失败种子相同，没有补种子。

| 初始识别检查，42 个有效场景 | 杯子 | 杯垫 |
| --- | --- | --- |
| 模型有输出 | 33 | 41 |
| 掩码与目标匹配，IoU≥0.5 | **30** | **40** |
| 有输出但认错物体 | 3 | 1 |
| 拒绝或未得到输出 | 9 | 1 |

**杯子与杯垫同时匹配：28 个场景。** 这里报告的是识别数量，不是完整任务成功率。42 个场景的真实目标在相机内均有可见像素，因而本批的未匹配并非“目标全在视野外”。掩码 IoU 包含无输出样本的均值为杯子 0.7123、杯垫 0.9480；不能据此推断抓取或放置效果。

### 杯子问题

- 认错：seed **1、14、46**。预测掩码与目标杯子交集均为 0，不是只分出了部分正确杯身。seed 1 选中了右上方容器；14、46 选中了画面上方其他物体，真实杯子仍在左侧。
- 竞争候选拒绝：seed **5、10、28、36、40、43、49**。多个语义/几何候选的排序分数差不到既定门槛，程序没有唯一选定杯子。不能把这 7 次直接解释成完全没看到杯子，其中多轮候选里已有实际目标，但同类容器干扰仍使身份选择不确定。
- 未得到通过检查的语义/几何候选：seed **11、48**。

这说明“颜色不作硬门槛”避免了固定颜色过滤，却不能独自解决目标身份问题：场景里其他杯、罐、奖杯和容器也可能满足粗几何；只有通用 `cup/mug` 语义和少量颜色加分，还不够稳定。该实验分支没有回写到现有放置控制器。

### 杯垫问题

- seed **17** 选成右下方较大的盘状物。它也能通过现有“接近桌面、相对平坦、尺寸范围”检查，但不是目标杯垫，独立掩码 IoU=0。
- seed **19** 未输出杯垫：语义候选集中在上方其他圆形物体，没有候选通过桌面平面检查；目标杯垫本身仍清楚可见。

因此应区分“相机看得见”“模型提出了正确候选”“最后选对并定位”三个环节，不能把几何检查通过当成目标身份已经正确。

### 执行与一致性

42 次感知请求均正常返回，视觉进程仅启动一次且已关闭。各轮记录 `task_actions_executed=0`、`vla_loaded=false`、`task_success_evaluated=false`；没有构造任务成功率字段。只有正常场景初始化/复位的运动，不存在初始化后的任务动作。冻结版本来源哈希前后相同。

排除 seed 0 首次视觉加载后，41 个有效场景平均感知墙钟时间约 **0.401 s**；不是任务完成时间，不包括环境初始化。

结论：杯垫在大部分有效场景中已可定位，但杯子身份区分仍是主要问题。不能直接把这个新候选分支接入抓取，更不能把 33 次杯子有输出说成 33 次认对。下一步可针对同类干扰、边缘目标和候选拒绝改进，再做初始感知对照；本批没有为提高数字而调阈值或重算候选。
