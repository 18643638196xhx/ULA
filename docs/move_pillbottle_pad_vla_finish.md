# 药瓶任务对照：传统接近，VLA 连续抓取与放置

## 这次改变什么

原方案是“传统接近 → VLA 抓取 → 传统搬运、下降、松爪、撤离”。本对照把括号中的“移动到垫子上方，再放置”整段也交给 VLA：**传统接近 → VLA 连续抓取、搬运、下降、松爪、撤手**。

没有一段传统控制先把瓶子搬到垫子上方；也不是抓后重新启动一次 VLA。WorldLA 每轮只重置一次，连续看图、输出双臂关节与夹爪动作，中途不因为闭爪而打断，因此不会把抓取时缓存的动作接到一个由传统控制改变过的新状态上。

这条入口仍使用明确给定的 base1 药瓶模型、RGB-D/FoundationPose 定位和标注接近。不是未知物体、无模型实验。默认接近参数与原传统放置对照一致，接触候选为 `all`；不采用效果较差的 `central` 接近消融。VLA 权重、完整任务指令、随机种子和动作预算保持一致，不训练新模型。没有新增试抬，也不执行传统闭爪、搬运、放置或撤离补救。

## 怎样判断结束

闭爪指令连续 3 个动作低于 0.05，只记录出现过闭爪，不停止 VLA，也不证明夹稳。之后打开指令连续 3 个动作不低于 0.95，才开始检查放置画面；每隔至少 10 个 VLA 动作检查一次。

检查使用当前 RGB-D 与已知 CAD 估计瓶底，重新识别蓝色垫子，并用机器人运动学计算 TCP。视觉估计的瓶底在垫子中心 XY 各方向 3 cm 内、高度差不超过 1.5 cm，估计瓶身倾斜不超过 15°，且 TCP 已离开可见瓶身范围至少 3 cm，才算一次通过。连续两次通过后停止。定位不可信就不通过这次检查，继续让 VLA 在剩余动作预算内执行，不把估计结果转换为传统控制目标。默认最多 300 个动作，耗尽仍未确认则停止并记为流程未完成。

这些是明确的人为视觉启发式，不是物理稳定性证明，也不是 RoboTwin 原始评分。模型位姿仍需通过原有 CAD/深度一致性检查，没有放宽配准门槛。控制停止后才读取官方成功条件，分别报告“视觉确认且官方成功”和“官方最终状态成功”；两者不能混用。视觉确认的时间也包含检查开销，不能直接当作纯 VLA 推理耗时。

## 真值边界与隔离

动作由 VLA 的图像、机器人状态和任务语言输入产生。传统接近使用已知模型/标注、视觉估计位姿、相机标定、机器人模型与实测状态、配置的桌面碰撞盒。视觉结束检查同样使用图像与已知 CAD，不读取实时药瓶/垫子仿真位姿、接触信息或机器人像素身份标签。在线官方成功检查和策略真值诊断被禁用；官方评分仅在控制结束后读取。

新增入口与适配器独立，原来的传统放置入口仍可使用，杯子、微波炉、点云药瓶、外部 VLA 和 RoboTwin 源码保持不变。

## 启动

```bash
cd /data1/xuhuixin/ula
GPU=7 bash scripts/run_move_pillbottle_pad_vla_finish.sh \
  --known-model 1 --known-approach annotated --known-contact-region all \
  --episodes 5 --seed 0 \
  --output /data1/xuhuixin/ula/results/pillbottle_vla_finish_new
```

输出目录必须为空。结果包含每轮 `result.json`、批次 `report.json`、初始/接近交接/最终三相机截图、视觉请求和完整 VLA 动作轨迹。没有连续视频。首轮含冷加载/编译；连续开发种子复测不是独立 50 次泛化评测。

seed 2 最终药瓶掉到地面。seed 4 最终没有放到垫子上，水平中心误差约 24.7 cm，双夹爪已打开。上述信息仅来自控制结束后的评测，不参与动作生成；没有记录中途实时物体真值，因此不据此断言 seed 4 是哪一步首先失误。

退出检查还有两个独立问题：VLA 放开瓶子后常停在瓶子附近，没有满足额外的 3 cm 撤手要求；瓶子遮住垫子后，“可见蓝色区域的中心”会偏离完整垫子的中心。例如 seed 0 当前视觉垫子中心比本轮初始视觉定位偏约 2.5 cm，导致瓶底与垫子的视觉偏差被放大。TCP 到点云包围盒的距离也不能证明真实夹爪是否仍接触瓶子。后续若要可靠地自动结束，应单独改进该观察器，不能通过在线读取官方真值解决。

五轮均执行到 300 个动作，不应把这批的运行耗时称为“平均完成时间”。全套回归在批次前为 228 项通过，杯子、微波炉、原点云药瓶及官方代码保护指纹一致，视觉工作进程已关闭。批次后只修正报告描述、异常评分恢复和“重新闭爪时清空连续退出计数”；本批所有退出检查均为不通过，历史结果保留，不改写为新版本实测结果。
