# 异常观测的有限次重新分割与补观测

## 目标与范围

新增显式选项 `--pointcloud-reobserve`，用于 pointcloud 模式的传统接近前与抓后放置前。
旧默认不变；原有 50 轮结果不覆盖，不把调试小批结果作为新成功率。
本改动只处理“看不清/分割异常时如何取得更可信的观测”，不同时改变放置精度、候选搜索、ICP 门槛或滑移设置。

```text
新观测 → 检查几何/画面边界
          ├─ 正常 → 原流程
          └─ 异常 → 改变 SAM 提示重新分割 → 再检查
                        ├─ 可信 → 继续
                        └─ 仍异常 → 腕部备用观测 → 匹配视角验证
                                           └─ 耗尽仍不可信 → 停止
```

不是对同一张图重复执行完全相同的确定性算法。重分割改变检测 ROI、正提示点及候选选择，腕部备用则实际使用另一视角。

## 异常判断不是杯子 CAD

当前检查使用本次 RGB-D 与本轮参考：

- 是否有足够有限的表面点、范围是否有效。
- 分割是否碰到图像边缘。
- 竖直范围 / 较小水平范围是否超过 2.2。
- 抓后范围对角线相对本轮抓前观测是否增长超过 1.6 倍。
- 抓后原有 ICP 是否通过残差、双向重叠率和估计倾斜门槛。

这些是启发式可信度条件，不是“已知杯子应当高多少厘米”。范围变化可能来自视角或遮挡，并不证明物体真的变形。
细长物体、局部可见表面可能被误拒绝；当前只在既有杯子任务上验证，不能据此宣称任意未知杯子泛化。
重复后仍不满足几何条件就停止，不用物体真值修正观测。

## 怎样重新分割

1. 使用本次 GroundingDINO 检测到的杯子框，取带少量边界的局部 ROI。
2. 在有效前景深度中，利用视觉桌面高度排除桌面层，以较低的前景层选取 SAM 正提示点；这适合当前桌面杯子被上方结构污染的情况，是显式启发式。
3. 深度提示不可用时退回框中心提示；不会改用仿真杯子位置。
4. SAM2 输出多个分割候选，先剔除无有效几何或纵向异常的候选，再在可信候选中选模型分数较高的一个。
5. 没有可信候选则报告失败，允许外层尝试下一视角，而不是强行返回最高分异常掩码。

没有使用机器人身份/连杆区域掩码，没有按机器人真值删除点，也没有用固定颜色阈值清洗点云。
输入仍是已有检测提示“blue cup”、RGB-D 与标定；SAM 候选选择变化不等于完整物体重建。
原有点云边缘处理和分位数裁剪保留。

## 接近前的顺序

最多三个观测候选：原始头部 → 重新分割的头部 → 重新分割的当前活动臂腕部。
在得到可信的几何范围前，不准备夹爪、不生成粗接近目标。
腕部候选必须保持头部杯垫目标，检查视觉桌面高度一致性，并标记腕部作为实际点云参考来源。

仅边缘截断而范围合理的“头部重分割”候选，可以用于有限粗接近，但不能直接启动 VLA：
必须走原有粗接近后的腕部补看门，截断未解决则停止。开启本选项会自动要求这一检查，即使没有单独指定 `--pointcloud-multiview`。
新模式下该腕部观测也先通过几何检查；异常时不根据它移动相机。

实际选中的参考写到 `selected_reference.npz`，不能继续偷偷使用第一次被拒绝的 `estimate.npz`。
接近到位后额外保存一帧腕部 RGB-D 与标定到 `wrist_reference_frame.npz`，不立即执行视觉模型。

## 抓后放置前的顺序

先重新取得头部观测，杯垫目标保持来自新头部深度。
如果主参考是头部：原始头部候选 → 头部重分割候选 → 腕部备用候选。
如果主参考本来是腕部，则只使用原始/重分割腕部候选与同相机主参考配准。

头部仍截断时，先触发一次重分割；重分割后只有几何条件及原有双向 ICP 门槛同时满足，才允许使用部分可见表面。
仍明确记录边缘截断，不能称为“杯子完整可见”。
腕部备用必须按需处理之前保存的抓前腕部帧，再与当前腕部帧配准。没有匹配参考、参考相机不一致或任一帧不可信就拒绝。
**不直接拿头部参考点云与腕部当前点云混配，不用旧杯垫位置替代新头部目标。**
最多三个当前候选，腕部备用额外处理一帧已保存参考；没有无限循环，不反复加载模型。
成功之前不做搬运规划，不松爪；全部失败时诊断保存在 `reobservation_failure` / `traditional_placement.reobservation`。

## 为什么没有新增异常后的自动挪手

当前版本先实现改变分割提示和换相机，不根据异常杯子估计直接生成新的观测运动。
原有粗接近后、有界且经过规划/到位检查的腕部居中步骤保留。
抓后杯子与腕部相机可能近似一起运动，简单挪手并不能保证改变它们的相对视角，因此本版不宣称实现了抓后的主动视角优化。

## 记录与计时

- 顶层：`pointcloud_reobservation` 记录开关、阈值、候选上限与信息依赖。
- 接近：`handoff.reobservation` 记录尝试、选择及抓前腕部帧路径。
- 放置：`traditional_placement.reobservation` 记录几何、ICP 与配对相机。
- 耗尽失败：`reobservation_failure` 保留完整尝试诊断。
- 原始与补充 RGB-D/估计分目录保存，不覆盖历史批次。
- 新调用计时为 `supplementary_perception`，相机采集仍为 `observation`，配准仍为 `pointcloud_registration`。
- 各阶段排他计时包括所有失败/重试请求。选中估计自身的 `timing_s` 只是该次调用，不能当作整段所有感知耗时。

感知与目标生成仍不读取杯子 CAD、元数据、物体仿真位姿。已有抓稳验证与最终评测的真值依赖并未因此消失。

## 使用

在现有关闭试抬滑移检查的命令中添加 `--pointcloud-reobserve`：

```bash
GPU=5 bash scripts/run_place_empty_cup.sh \
  --mode hybrid --approach-mode pointcloud \
  --pointcloud-multiview --pointcloud-reobserve \
  --grasp-retries 1 --grasp-stall-steps 120 \
  --registration-max-rmse 0.012 --registration-max-tilt 35 \
  --grasp-handoff contact-trial-lift --contact-gripper-threshold 0.05 \
  --skip-trial-slip-check --episodes 50 --seed 0 \
  --output /data1/xuhuixin/ula/results/reobservation_50eps_repeat
```

以上仅为复现示例，需先确认 GPU 空闲并使用新目录；本次适配不自动运行完整 50 轮。
