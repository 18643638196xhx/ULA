# ULA 示范相对接近模块改进说明

## 1. 改进背景

ULA 的支持面放置任务采用以下分层流程：

```text
RGB-D 定位目标物体
→ 传统控制移动到物体附近
→ VLA 完成局部调整与抓取
→ 传统控制搬运和放置
```

为了让传统控制的接近位置更符合 VLA 的训练起点，之前加入了“示范相对接近位姿”：从一条官方示范中提取闭爪前的接近关系，再迁移到 random 场景中的目标物体。

第一版实现出现了明显退化：

| 编号 | 问题 | 证据 |
|---|---|---|
| A1 | 示范相对接近成为负优化 | cup 90%→60%、pillbottle 30%、fan 25% |
| A2 | 照搬示范腕姿后，机械臂实际没有到达目标 | cup 4 场、fan 3 场失败，部分位置误差约 19 cm |
| A3 | 示范候选仍然无法通过 IK | pillbottle 6/10 `planning_failed` |
| A4 | 几何兜底主要改变姿态，没有充分改变位置 | pillbottle seed 3 两只机械臂候选均 IK 失败 |

## 2. 根因分析

### 2.1 把示范绝对腕姿误当成物体相对姿态

官方示范只提供机器人轨迹，没有提供示范帧中物体的可靠六维位姿。因此，我们只能知道示范末端在世界坐标系中的朝向，不能证明这个朝向是相对物体定义的。

第一版把该绝对腕姿直接搬到新的 random 场景。当目标换到另一侧、改用另一只手，或物体朝向发生变化时，这个腕姿可能很难到达，即使 CuRobo 找到轨迹，机器人也可能产生较大的实际跟踪误差。

### 2.2 混淆了 TCP 与 EE 的语义

当前视觉锚点是物体可见包围框顶部中心，它描述的是夹爪工具中心应该接近的位置，因此应当作为 TCP 目标。

第一版先把该点当成 EE 位置，随后又应用了一次约 12 cm 的 `EE_to_TCP` 标定偏移。这样会把工具偏移重复加入目标，在部分姿态下形成接近 19 cm 的末端位置误差。

正确关系应为：

```text
目标 TCP = 当前物体视觉锚点 + 示范接近位移
目标 EE  = 目标 TCP × inverse(EE_to_TCP)
```

### 2.3 候选搜索只覆盖了腕姿，没有覆盖真正不同的位置

旧几何兜底以物体某一侧的固定位置为中心，主要枚举偏航角和俯仰角。对于 pillbottle seed 3，候选虽然很多，但 TCP 位置高度集中在同一区域，所以全部 IK 失败。

因此，“增加更多角度”不能解决 A4，必须同时生成不同的空间位置。

## 3. 改进后的方法

### 3.1 示范只提供接近方向和距离

对于当前九个 `visual_bounds_top_anchor` 先验，在线阶段只迁移：

- 从物体交互位置到示范接近位置的平移方向；
- 这段平移的距离。

不再迁移示范中的世界坐标绝对腕姿。左右手切换时，只镜像接近位移的 X 分量。

如果未来示范和在线视觉都能提供可靠的物体六维位姿，则可以使用严格的 `object_6d` 模式，在物体坐标系中迁移完整位姿。

### 3.2 腕姿来自当前机械臂的安全几何模板

新的 `visual_bounds_top_anchor` 流程使用当前任务、当前机械臂已经生成的几何腕姿模板。示范决定“从哪个方向、离物体多远”，几何模块决定“当前这只手应采用什么朝向”。

这样可以避免把右手示范的绝对姿态直接套到左手，也不会因为物体位置变化而保留不合理的世界坐标腕姿。

### 3.3 明确以 TCP 为视觉锚点

新的计算顺序为：

```text
当前 RGB-D 物体包围框顶部中心
→ 加上示范接近位移，得到目标 TCP
→ 使用当前安全腕姿设置 TCP 朝向
→ 通过机器人标定反算目标 EE
→ 交给 CuRobo 规划
```

结果审计中明确记录：

```text
anchor_semantics = TCP_on_current_visual_object_surface
stored_demo_absolute_rotation_applied = false
ee_tcp_offset_applied_exactly_once = true
```

### 3.4 增加通用的位置壳层

当示范位置不可达时，几何兜底现在生成三类位置：

1. 原有的机械臂侧边界位置；
2. 物体朝向当前 TCP 一侧的可见表面位置；
3. 从该表面继续朝机械臂方向移动一个当前物体观测半径的位置。

第三类位置的距离来自当前 RGB-D 包围框的三维尺寸：

```text
观测半径 = 0.5 × 物体包围框三维对角线长度
```

它不是为杯子、风扇或药瓶单独设置的固定坐标，因此可以复用到其他物体。当前位置只决定候选，最终是否可达仍由 CuRobo 的 IK、碰撞检查和轨迹规划决定。

## 4. 当前候选顺序

```text
1. demo_exact
   示范方向和距离迁移到当前物体

2. demo_visual_uncertainty_neighbour × 4
   按当前点云分辨率生成视觉误差邻域

3. demo_safe_orientation_variant × 最多 2
   保持示范位置，尝试当前几何模块提供的其他安全腕姿

4. geometry_bounds_fallback
   搜索不同位置、偏航角和俯仰角

5. CuRobo
   按顺序规划，执行第一条可行轨迹
```

一旦某条轨迹开始物理执行，系统不会在执行后继续尝试其他候选，避免机械臂移动后仍使用旧观测规划。

## 5. 针对旧失败样本的复验

| 任务与 seed | 原问题 | 改进后结果 | 位置误差 | 姿态误差 |
|---|---|---:|---:|---:|
| `place_empty_cup` seed 6 | 执行后未到位 | 通过 | 2.04 mm | 0.30° |
| `place_fan` seed 7 | 执行后未到位 | 通过 | 1.83 mm | 0.27° |
| `move_pillbottle_pad` seed 0 | IK 失败 | 通过 | 1.97 mm | 0.31° |
| `move_pillbottle_pad` seed 3 | 所有固定位置候选 IK 失败 | 通过 | 3.28 mm | 0.34° |

前三个样本使用第一条“示范方向 + 当前安全腕姿”候选直接成功。

pillbottle seed 3 使用位置壳层中的外侧候选成功。其目标 TCP 从原本集中在物体侧边的位置，移动到朝当前机械臂方向的可达区域，说明该场失败的根因确实是位置覆盖不足，而不是简单缺少更多腕部角度。

上述结果都是接近阶段的到位结果，不代表 VLA 抓取、传统搬运和最终放置已经成功。

## 8. 单轮运行耗时分析

当前一轮完整实测约为 **139 秒**：

| 阶段 | 耗时 | 约占总时间 |
|---|---:|---:|
| 感知：统一视觉与 CAD 校验 | 约 70 s | 50.4% |
| 场景初始化：包括 `check_stable` 200 步 | 约 21 s | 15.1% |
| VLA 抓取：失败时跑满 300–500 步 | 约 40 s | 28.8% |
| 快照保存 | 约 4 s | 2.9% |
| 其余流程 | 约 4 s | 2.9% |

这组数据说明，当前耗时的主要来源并不是示范候选或 CuRobo 的接近规划，而是以下三项：

1. **统一视觉与 CAD 校验。** 单次约 70 秒，占总时间一半。若每轮重新加载视觉模型，模型加载、特征计算和多个候选的 CAD 核验都会重复发生。
2. **失败的 VLA rollout。** 抓取没有成功时仍执行到 300–500 步上限，约消耗 40 秒。成功样本通常不会完整消耗这段预算，因此失败率也会显著抬高平均时间。
3. **仿真初始化。** `check_stable` 的 200 个物理步属于评测环境准备，而不是 ULA 接近、抓取或放置动作本身。报告算法执行时间时应与控制阶段分开统计。

### 8.1 优化优先级

第一优先级是让统一视觉进程在多轮实验之间常驻：

```text
首次加载 Grounding/SAM/CAD 资源
→ 后续 episode 只传入新的 RGB-D
→ 复用模型、CAD 特征和已编译算子
```

第二优先级是增加通用的 VLA 无进展终止条件。它不判断官方任务是否成功，只根据一段时间内的机器人状态判断策略是否已经停滞，例如：

- TCP 位移和转动持续接近零；
- 夹爪命令长期重复，但没有形成新的机械臂运动；
- 动作块在多个重规划周期内重复；
- 已超过从成功示范统计得到的正常局部操作时长范围。

满足无进展条件后应停止当前轮并记录 `vla_no_progress`，而不是继续跑满 300–500 步。该机制必须根据机器人状态与动作历史判断，不能读取物体真值或官方成功条件。

第三优先级是提供两套时间口径：

```text
端到端时间：场景创建到官方判定结束
控制时间：感知完成后，传统控制 + VLA + 后续控制
```

场景初始化和调试快照仍应保留在端到端时间中，但不能混入控制器本身的速度比较。快照可在正式成功率评测中改为只保存失败场或异步保存，以减少磁盘同步开销。

### 8.2 不应采用的提速方式

- 不能为了提速跳过 random 场景稳定性检查后仍与官方结果直接比较；
- 不能缩短 VLA 步数后把“达到步数上限”误报成抓取失败原因；
- 不能删除接近到位检查，否则会重新引入 A2 中“规划成功但实际未到位”的问题；
- 不能通过减少视觉候选而牺牲目标身份与 CAD 一致性，除非重新验证定位通过率。

## 9. 当前结论与边界

本次修改已经解决旧失败样本中的两个明确机制问题：

1. 示范绝对腕姿和重复 TCP 偏移造成的大幅到位误差；
2. 几何兜底只改变姿态、不充分改变位置造成的连续 IK 失败。

但目前不能仅根据四个定向样本宣布 A1 的整体成功率已经恢复。下一步需要在同一 random 配置下重新批量评测 cup、pillbottle 和 fan，并分别统计：

- 传统接近通过率；
- 各类候选的最终选中次数；
- 全部候选 IK 失败次数；
- 规划尝试次数与接近耗时；
- 接近成功后的 VLA 抓取成功率；
- 完整任务成功率。

只有完成同配置批量对照后，才能判断示范相对接近从“负优化”变成了稳定收益，还是仅修复了部分失败类型。
