# 大桶定位：固定俯视覆盖与同位姿跨视角核验

日期：2026-11-12。

## 修改范围

默认单视角模式不变。新增显式 `--multi-view` 实验模式，使用原头部相机和一个固定的工作台俯视 RGB-D 相机。俯视相机的工作空间坐标为 `[0,0,2.2]`、朝向竖直向下，全部任务和 seed 共用，不读取任何目标位置、分割标签或功能点来布置相机。这个模式需要实际具备对应相机，不应把额外相机当成原单相机的免费算法收益。

增加 `VisionConfig.require_cross_view_cad`，默认关闭。开启后，一个候选位姿先通过原来的三角面距离和本视角渲染核验，再投影到另一台相机中。对**同一个世界坐标 CAD 位姿**使用另一视角独立测得的整幅深度核验，不要求另一次分割必须成功。不能拿两台相机各自独立得到的不同位姿当成相互支持。这个检查只证明几何相容性，不单独证明语义身份。

跨视角证据区分三种情况：

- `supported`：另一视角可见部分通过原来的渲染距离、比例及自由空间门槛。
- `contradicted`：有足够可见像素，而且观测到空地、深度不符等矛盾。无论其他视角是否支持，都拒绝。
- `unobservable`：被遮挡、超出视野或没有足够有效深度，不计为支持，也不等同于错误。当所有其他视角都未知时，仅在主视角的分割及 CAD 渲染轮廓都不触图像边界、并已通过主视角全部原检查时，允许保留结果，同时标为 `unobservable_primary_unclipped`，不声称已获得双视角确认。主视角也被截断则拒绝。

中间版 v2 要求第二个分割掩码表面距离通过；v3 改为独立场景深度但仍要求第二视角正面支持，两个版本各四个小样本联合定位均未通过。v4 进一步区分“看不见”和“看到矛盾”；所有中间记录保留，不能据此宣称成功率已恢复。

多视角模式中的 `position_world` / `bounds_world` 明确来自最终证据的参考相机，该相机通过 `position_reference_camera` 记录；保留多视角点云供跟踪与诊断。这样不会将融合点云的范围中心和某台相机的局部可见中心混用。评分使用预测保存时明确选择的证据相机，而不是看完评分后挑选更有利的视角；标签只在预测锁定后读取。

## 取景验证

先试验了固定前方工作区视角，但实际画面仍受支架遮挡，该版本只进行了冒烟验证，没有进行 50 场正式评测。改用固定俯视布局后，传感器画面中大桶轮廓能完整进入图像：

[无动作、无推理的固定俯视画面](/data1/xuhuixin/ula/results/workspace_overhead_check_20261112_v1/workspace_camera.png)

注意：相机数量改变也可能改变环境的随机数消耗，因此相同 seed 不自动保证和原单相机版具有完全相同的随机摆放。后续比较应明确这是新增传感配置实验，不能未经图像一致性核验宣称逐场严格配对。
